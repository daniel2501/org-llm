* Summary

*Summary.* This page is the live walkthrough surface for Phase 26.1 — per-component
core-vs-addable decisions. Each component is a heading with the cut criterion applied;
the user walks through one at a time, lands a decision (CORE / ADDABLE / EDGE), and
commits this page as the persistent record of the cut.

*Expanded.* The cut criterion comes from DEC-009 (curated core agents + extension path)
sharpened by the 2026-05-05 mission walk: /if this disappeared from core, would the lead
value (β: dream-state vault via agents + dbt-shaped opinionated distro) still ship?/
Yes → not core; route to extension path. No → core, earns its keep. The mission walk
produced an initial split of ~30 components: ~15 pre-classified CORE, ~16 pre-classified
ADDABLE, and 7 EDGE components that need argument. Protocol is one component per turn —
decide together, fill the Decision + Walkthrough notes fields, repeat. This page is the
persistent record of the cut; once complete, follow-up extraction TODOs land in
dev-tracker.org under Phase 26.

* The cut criterion

DEC-009 framing, sharpened:

#+begin_quote
If this component disappeared from core, would the lead value still ship?
- Yes → not core; move to extension path.
- No  → core, earns its keep.
#+end_quote

Lead value (β):
- Dream-state vault via agents (the vault thinks with you)
- dbt-shaped opinionated distro (curated, composable, FOSS-first)

Tier model (DEC-013, two-tier tools):
- Tier 1 — core: ships with the distro, load-bearing for β.
- Tier 2 — addable: discoverable, installable, not required for β.

EDGE means we haven't yet agreed which tier; it gets argued explicitly in this page.

* Decision protocol

- Walk one component at a time.
- Decide together: CORE / ADDABLE / EDGE.
- Annotate decision below the component heading with:
  - Timestamp (ISO date)
  - Agreed outcome (CORE / ADDABLE / EDGE)
  - Brief rationale (1–2 sentences)
  - Follow-up if any (extract path, refactor needed, plugin loader entry)
- When all components decided, file follow-up TODOs for the actual extractions in
  dev-tracker.org § Phase 26.
- Don't re-categorize during walkthrough — EDGE stays EDGE until argued.
