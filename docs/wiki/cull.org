* Summary

*Summary.* This page is the live walkthrough surface for Phase 26.1 — per-component
core-vs-addable decisions. Each component is a heading with the cut criterion applied;
the user walks through one at a time, lands a decision (CORE / ADDABLE / EDGE), and
commits this page as the persistent record of the cut.

*Expanded.* The cut criterion comes from DEC-009 (curated core agents + extension path)
sharpened by the 2026-05-05 mission walk: /if this disappeared from core, would the lead
value (β: dream-state vault via agents + dbt-shaped opinionated distro) still ship?/
Yes → not core; route to extension path. No → core, earns its keep. The mission walk
produced an initial split of ~30 components: ~15 pre-classified CORE, ~16 pre-classified
ADDABLE, and 7 EDGE components that need argument. Protocol is one component per turn —
decide together, fill the Decision + Walkthrough notes fields, repeat. This page is the
persistent record of the cut; once complete, follow-up extraction TODOs land in
dev-tracker.org under Phase 26.

* The cut criterion

DEC-009 framing, sharpened:

#+begin_quote
If this component disappeared from core, would the lead value still ship?
- Yes → not core; move to extension path.
- No  → core, earns its keep.
#+end_quote

Lead value (β):
- Dream-state vault via agents (the vault thinks with you)
- dbt-shaped opinionated distro (curated, composable, FOSS-first)

Tier model (DEC-013, two-tier tools):
- Tier 1 — core: ships with the distro, load-bearing for β.
- Tier 2 — addable: discoverable, installable, not required for β.

EDGE means we haven't yet agreed which tier; it gets argued explicitly in this page.

* Decision categories (revised 2026-05-05 mid-walk)

The original cull rubric was binary (CORE / ADDABLE) plus an
explicit EDGE bucket for cases needing argument. Mid-walk the
user sharpened to a *ternary*:

#+begin_quote
- *CORE* — ships, *on by default*. Mandatory part of the lead
  value (β: dream-state vault via agents + dbt-distro shape).
- *CORE_DISABLED_BY_DEFAULT* — ships in the install, *off by
  default*. User opts in via a knob. Bundled but quiet — they
  get the tooling without it nagging or being a footprint
  cost.
- *COMMUNITY IDEA* — does NOT ship in core. Lives in the
  extension path (per [[id:a4d1f7c3-6e29-4b8a-9f15-3d8e2c7b91a5][DEC-009]]). User or community can
  develop. The decision is "we won't carry this in core" —
  not "we won't allow this."
#+end_quote

This three-way split extends DEC-009 (curated core + extension
path) from binary to ternary; the middle category collapses
the prior "ADDABLE" + "EDGE" buckets when the answer is
"keep, but quiet." Filed as DEC-014 candidate when the walk
wraps.

* Walkthrough convention

- *p* (or *preclassified*) — ratify the pre-classified verdict
  as-is. Tight shorthand for the common case where the
  pre-classification holds up.
- *CORE* / *CORE_DISABLED_BY_DEFAULT* / *COMMUNITY IDEA* —
  explicit verdict, possibly with a one-line rationale.
- *flip → <X>* — re-classify against the pre-class (e.g.
  "flip → COMMUNITY IDEA"); rationale required.

*Agent-ification default* (added 2026-05-05 mid-walk): every
CORE / CORE_DISABLED_BY_DEFAULT verdict also means *"surface
this component as an @-agent representative"* — an
agent persona responsible for / knowledgeable about / able to
drive the component. Default applies unless: (a) verdict is
COMMUNITY IDEA (community decides representation), or (b) user
explicitly says "no agent" on the component.

Mapping component → agent is a *separate design exercise*
(post-cull). One agent may own multiple components (e.g. a
=@librarian= owning indexer + search + vault_facts), so
agent-ifying 15 CORE components doesn't mean 15 new agents.
The curated core team stays ≤6 (per [[id:a4d1f7c3-6e29-4b8a-9f15-3d8e2c7b91a5][DEC-009]]); component
ownership is the routing layer below.


* Decision protocol

- Walk one component at a time.
- Decide together: CORE / ADDABLE / EDGE.
- Annotate decision below the component heading with:
  - Timestamp (ISO date)
  - Agreed outcome (CORE / ADDABLE / EDGE)
  - Brief rationale (1–2 sentences)
  - Follow-up if any (extract path, refactor needed, plugin loader entry)
- When all components decided, file follow-up TODOs for the actual extractions in
  dev-tracker.org § Phase 26.
- Don't re-categorize during walkthrough — EDGE stays EDGE until argued.
