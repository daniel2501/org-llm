* What this is

The detailed phase catalog and forward-looking project plan for
=org-llm=. The README has a short overview pointing here; this is
the source of truth for "what's done, what's next, what's
later."

Phases are organic milestones, not a calendar cadence. A phase
advances when a chunk of work feels done and the next chunk has
shape. =Phase X.Y= sub-phases let one parent theme (e.g. "insight
cards" = Phase 12) ship in slices without renumbering the world.

** How to read this page

- *Status* on each phase: =shipped=, =in progress=, =planned=,
  =wishlist=. Shipped phases have a commit hash anchor; planned
  ones reference the code TODO that names them.
- *Phase numbers can have gaps* (no Phase 4, no Phase 14). When a
  chunk got absorbed into the previous or next milestone, the
  number was retired rather than reassigned.
- *Sub-phases stay open* until the parent retires; a Phase 12.6
  that's still =planned= doesn't block a Phase 13 that already
  shipped.

* Shipped — Phase 17: live sidebar status panel              :shipped:

The next big feature push. The opencode TUI sidebar currently
shows opencode's defaults (mcp / lsp / files / todo widgets);
the sidebar_title was branded "org-llm •" in Phase 16.2 but the
content beneath is still default. Phase 17 replaces it with a
live, refreshing org-llm panel.

** Scope

- *Live status surface* — vault counts (=N nodes · M stale ·
  last gather Xm ago=), active palette + knob mix, MCP server
  status, auto-embedder daemon state, hardware probe verdict.
- *Common feature links* — clickable / keybind-jumpable rows for:
  - =doctor= — quick health probe
  - =library= — recent vault activity
  - =insights= — open the cards dialog (already exists; sidebar surfaces it)
  - =wiki= — open the wiki index
- *SensorLog stream* — the existing =sensor_log= table records
  every probe cycle (battery / CPU / mem / thermal / network /
  ollama / auto-embedder); surface a rolling tail of recent
  alerts in the sidebar so anomalies are visible without
  running =doctor=.

** Implementation surface

- =sidebar_content= slot override (TSX in
  =extensions/opencode/src/slots.tsx=); same plumbing as the
  Phase 16.2 =home_logo= override.
- New launch-time JSON file =.opencode/sidebar-status.json=
  populated alongside =insight-cards.json=. Plugin reads this
  on mount and re-reads on a tick.
- Plugin registers a refresh interval; on each tick re-reads the
  JSON. (The launch flow's =auto_embedder= daemon already writes
  current vault stats to the DB; the sidebar JSON is a thin
  serialisation pass.)

** Status

Shipped 2026-04-30. v1 is launch-time only; the auto-embedder
re-write hook (so the panel stays live without relaunching) is
the next iteration. Live data refreshes on a 15s tick reading
the JSON file, so an external writer (auto-embedder cycle, a
=doctor= run, etc.) can update the panel without coupling to
opencode's runtime.

* Wishlist — no commitment                                   :wishlist:

** Voice / TTS bridge
A =org-llm voice= subcommand that pipes the chat surface through
local TTS (e.g. Piper) for hands-free vault interaction.

** Multi-vault federation
The current data model assumes one vault per install. Federation
(read across vaults; write to one) opens the door to shared
team knowledge bases.

** Browser extension
A capture surface for arbitrary web pages, bookmarklet-style.
=capture --url= already exists in the CLI; this would be the
zero-keypress front door.

** Inline embeddings refresh
Today =auto_embedder= runs as a daemon. Inline (per-edit) refresh
would make new captures searchable instantly without waiting for
the next cycle.

* How phases get numbered                                    :process:

- A *Phase X* is a coherent theme that ships in slices.
- *Phase X.Y* sub-phases are the slices. They land independently;
  the parent phase isn't "done" until the last slice ships AND no
  more =planned= slices are outstanding.
- *Numbers can be skipped or retired* when a chunk gets absorbed
  into a different theme. Phase 4 was absorbed into Phase 5; Phase
  14 was absorbed into Phase 15. The retired number doesn't get
  reassigned.
- *Commit messages* prefix the phase: =feat(insights): Phase 12.5 —
  engagement table=. Grep =git log --grep="Phase "= to find every
  phase landing.
- *Sub-phase numbering* is loose. 12.6 + 12.7 are reserved for
  planned work; if a 12.8 idea shows up first, it can take the
  next available number.
