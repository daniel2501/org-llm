* What this is

The detailed phase catalog and forward-looking project plan for
=org-llm=. The README has a short overview pointing here; this is
the source of truth for "what's done, what's next, what's
later."

Phases are organic milestones, not a calendar cadence. A phase
advances when a chunk of work feels done and the next chunk has
shape. =Phase X.Y= sub-phases let one parent theme (e.g. "insight
cards" = Phase 12) ship in slices without renumbering the world.

** How to read this page

- *Status* on each phase: =shipped=, =in progress=, =planned=,
  =wishlist=. Shipped phases have a commit hash anchor; planned
  ones reference the code TODO that names them.
- *Phase numbers can have gaps* (no Phase 4, no Phase 14). When a
  chunk got absorbed into the previous or next milestone, the
  number was retired rather than reassigned.
- *Sub-phases stay open* until the parent retires; a Phase 12.6
  that's still =planned= doesn't block a Phase 13 that already
  shipped.

** 17.1j–o: slow-LLM watcher + cloud relaunch
- New [[file:../../extensions/opencode/src/slow-llm-watch.tsx][=extensions/opencode/src/slow-llm-watch.tsx=]] — watches
  =message.updated= events from outside the LLM loop. If the AI
  hasn't started responding within =sidebar_slow_llm_threshold_ms=
  (default 25s), the plugin aborts the call, runs
  =org-llm doctor --power-boost --no-diagnose= as a subprocess,
  and injects the diagnostic into chat as a permanent record.
- =sidebar_slow_llm_confirm= (default true): plugin waits for
  =/syscloud= confirmation before applying. Users can flip false

- =sidebar_slow_llm_auto_relaunch= (default true): on apply, the

  auto-resubmits via cloud — no manual "Ctrl+C twice + rerun."

** 17.1k–s: =/sys*= slash family + LLM proxy
- New [[file:../../extensions/opencode/src/sys-commands.tsx][=extensions/opencode/src/sys-commands.tsx=]] — implements
  =/sysdoctor=, =/sysstats=, =/sysmodels=, =/sysrecent=,
  =/sysreclaim=, =/syscloud=, =/sysmenu=, =/sysmodel <name>=,
  =/sysapply <numbers>=, =/sysscroll-{up,down,pgup,pgdn}=. Each
  runs a CLI subcommand or local action and injects the output
  into chat as a noReply user message — so diagnostics, model
  lists, and recent activity all live alongside the conversation
  instead of vanishing in transient toasts.
- New [[file:../../org_llm/llm_proxy.py][=org_llm/llm_proxy.py=]] (~1600 lines,
  [[file:../../scripts/test_llm_proxy.py][=scripts/test_llm_proxy.py=]] with 38 cases) — HTTP shim
  between opencode and ollama. opencode fires the LLM call the
  moment a message is submitted; there is no plugin-side hook
  before the request leaves. The proxy intercepts at the HTTP
  layer with a chain of interceptors that can short-circuit the
  call entirely. Ships with 13 interceptors:
  - =intercept_no_llm_flag=, =intercept_sys_commands= — the =/sys*=
    family + =--no-llm= arg → empty response, ollama untouched.
  - =intercept_response_cache=, =intercept_probe_cache= — cache
    exact prompt hits and repeated provider probes.
  - =intercept_static_slashes= — handwritten responses for =/menu=
    =/help= =/config= (no-LLM equivalents of opencode's
    LLM-driven slashes).
  - =intercept_time_grounding=, =intercept_pii_redact= — inject
    current date, redact secrets before forwarding.
  - =intercept_tool_call_repair=, =intercept_qwen3_no_think= —
    fix common LLM-emitted malformed tool calls; auto-inject
    =/no_think= for qwen3.
  - =intercept_model_routing=, =intercept_md_skills= — pick model
    by query shape; run =.md=-defined slash commands as
    subprocesses (=exec:= frontmatter or built-in skill names).
  - =intercept_prompt_slim= — strip the MCP catalog from the
    system prompt for queries that don't need tools (saves ~22KB
    per turn against local models).
  - =intercept_local_only= — catch-all kill switch
    (=proxy_local_only=true=); short-circuits every chat call so
    the user can lock the session into "no LLM at all" mode.
- =inject_args_in_slashes= knob (default false) — proves we can
  mutate =.opencode/command/*.md= at launch (appends =$ARGS= to
  static =.md= bodies so user-typed flags reach the proxy).

** Tool-call reliability warning for under-spec'd local models

Discovered 2026-05-02: a user query as simple as "count of org
files?" hung indefinitely on =phi4-mini= because the model spun
reasoning chains without ever emitting an MCP tool call. The
slow-LLM watcher caught the hang at 25s and ran
=doctor --power-boost= (Phase 17.1j working as designed), but
the user's *first* impression was a hung TUI.

Fix: at launch, check =chat_model= against a known-unreliable
list (phi4-mini, gemma3:<12b, etc.) and either:
- emit a yellow toast suggesting a swap to llama3.2 / qwen3:4b
- pre-flight ping the configured model with a tool-shaped probe
  ("respond with a tool call to time"), and warn if it
  reasoning-chains instead of calling
- doctor's =--power-boost= already recommends upsizing — extend
  it to ALSO recommend swapping to a smaller-but-tool-reliable
  model when the current one is tool-unreliable rather than just
  too big

The bundled =chat_model= default is already =llama3.2= so fresh
installs are fine; this is for users who manually overrode it
without realising the tool-calling implications.

** Action bridge (file-based external dispatch)              :shipped:
:PROPERTIES:
:STATUS: shipped
:END:

Shipped 2026-05-02 (commit =fe92e18=, extended in =-iter9=). A
generic JSON-file dispatch channel between any external client and
the running opencode TUI. The plugin reads
=<org_dir>/.opencode/sidebar-action.json= on a 250 ms tick and
dispatches when =ts > last_seen=. Handlers reuse the same code
paths the in-TUI surface uses, so the only difference between
"user clicked something" and "Doom wrote a JSON file" is the
trigger source.

Why it exists: opencode's slash-command validator rejects vterm-
injected =/sys*= commands at submit time even when the same names
work when typed manually. After 8 iterations on validator
workarounds, abandoned the slash-router path entirely. The file
bridge sidesteps every key conflict, terminal protocol quirk,
and registry rule.

Schema (=v: 1=):

| =action=          | Fields                            | What it does                          |
|-------------------+-----------------------------------+---------------------------------------|
| =scroll=          | =direction= (-1/+1), =unit=       | Sidebar scroll line / page            |
| =slash=           | =slash= (e.g. =/sysdoctor=)       | Generic /sys* dispatch                |
| =refresh-status=  | (none)                            | Force re-read of sidebar-status.json  |
| =toast=           | =title=, =message=, =variant=     | Surface a toast in the TUI            |
| =prompt-fill=     | =text=                            | Pre-fill prompt; user submits         |
| =prompt-submit=   | =text=                            | Pre-fill AND submit                   |

Doom bindings under =SPC l y= track the action types:

- =j= / =k= / =J= / =K= — scroll line/page
- =d= / =s= / =r= / =m= / =c= / =M= / =i= — /sys family
- =p= / =P= — prompt fill / submit
- =R= — send region as question
- ===/=~= — refresh-status / toast (notify)
- =q= — quit opencode (still vterm-send-string, only path that
  must reach opencode AFTER the bridge can no longer dispatch)

** 18.6: Cloud-first + synth tools + ctx-overflow retries     :shipped:
:PROPERTIES:
:STATUS: shipped
:END:

Shipped 2026-05-02. Three proxy-side fixes for low-RAM/thermally-
throttled hardware that turned the cloud failover path from a
fallback into a primary route:

- *=intercept_synth_tool_call= (synthetic tool calls).* Models on
  =_PROXY_NO_TOOL_STEMS= (gemma, gemma2, gemma3, phi3, phi3.5,
  llava, deepseek-coder) lack native tool calling. The proxy now
  strips =tools= from the request, injects a system prompt
  describing each tool with a =<tool_call>{...}</tool_call>=
  contract, calls upstream non-streaming, parses any tool block
  out of the reply, and reshapes into proper OpenAI =tool_calls=.
  Gemma users get full MCP/RAG with ~70-80% accuracy on simple
  single-tool calls.
- *Cloud-first bypass (=proxy_cloud_first=true=).* Skip the local
  upstream entirely on chat completions; route directly through
  =_failover_to_cloud=. Saves =proxy_first_byte_timeout_ms= per
  request when local hardware can't deliver. Onboarding step 6c
  offers it automatically when free RAM falls below 1.2× the
  configured =chat_model='s footprint.
- *Context-overflow retry chain.* Cloud free-tier models cap at
  32k; opencode's 64-tool MCP inventory alone is ~19k tokens.
  When cloud returns 400 with "context length" / "maximum
  context", the proxy retries first with =_compress_tools_for_failover=
  (descriptions trimmed to 80 chars, schemas stripped of examples
  and long fields — drops 64 tools from ~19k → ~3k tokens; model
  still knows tool names + arg shapes), then with =tools= removed
  entirely. Audit labels: =cloud_failover_compressed_tools=,
  =cloud_failover_no_tools=.

Default-bumps that landed in the same wave (auto-promoted on
existing DBs by =db.promote_stale_defaults=):
- =proxy_first_byte_timeout_ms=: 8000 → 30000
- =sidebar_slow_llm_threshold_ms=: 25000 → 45000

Net user-visible impact: a tools-using prompt on RAM-constrained
hardware dropped from ~40s end-to-end (30s local stall + 10s
cloud) to ~9.5s direct via cloud-first.

** Citation post-processor

After a forwarded =ask_notes= reply streams back, append a
deterministic source list (=[#node-id]= markers + a footer block)
keyed on the nodes the proxy saw the LLM retrieve. Removes the
LLM-cooperation dependency for grounded answers — citations are
guaranteed even when the model "forgets" to cite.

** Tool-result memoisation

Same MCP tool call (same args) within a configurable window →
return the cached result without round-tripping. Saves the local
model from regenerating the same =search_notes= → =get_node= →
read response chain when the user asks variations of the same
question.

** Skill-matching on free-form text

Extend =intercept_md_skills='s fuzzy matcher beyond the current
hardcoded patterns ("save this thought" → capture). Build an
embedding-keyed index of all registered skills' descriptions and
route free-form messages to the closest skill instead of the LLM
when similarity exceeds a threshold. Falls back to the LLM
cleanly when nothing matches.

** Per-turn model routing

Today =intercept_model_routing= runs at launch and sticks. Move
the decision per-turn: cheap qwen for "what's 2+2", smart cloud
for code generation, local-only for vault queries. The proxy
already sees every request body; the router just needs to rewrite
=model:= before forwarding.

** Auto-summarisation of long context

When the conversation history exceeds N turns, replace the
earliest turns with one-line LLM-generated summaries before
forwarding. Local models re-prefill the entire history every turn;
this keeps local-only sessions usable past 50+ turns without
falling off a cliff.

** Stream-time tool-call repair

=intercept_tool_call_repair= currently fixes the request body
(LLM-emitted bad calls in completions). The streaming-response
counterpart: many local models emit malformed JSON tool calls
mid-stream. Repair them on the fly so opencode's tool-use loop
doesn't error out.

** Provider-failure fallback

If upstream returns 5xx, connection-reset, or stalls past a
configurable threshold, transparently retry against the cloud
provider (or a different local model). Today the user sees
opencode's raw error UI; the proxy can recover before it bubbles.

** Voice / TTS bridge

A surface where the user can ask =org-llm= to open a specific org

- *opencode side* — a slash like =/edit-note <slug>= that opens

sketch:

- *triager* — vault hygiene: =find_stale=, =list_orphans=,
  =rescore_embeddings=, =auto_tag=. Periodic-maintenance flavour.
Each agent ships as a =.opencode/agents/<name>.json= file the

* How phases get numbered                                    :process:

- A *Phase X* is a coherent theme that ships in slices.
- *Phase X.Y* sub-phases are the slices. They land independently;
  the parent phase isn't "done" until the last slice ships AND no
  more =planned= slices are outstanding.
- *Numbers can be skipped or retired* when a chunk gets absorbed
  into a different theme. Phase 4 was absorbed into Phase 5; Phase
  14 was absorbed into Phase 15. The retired number doesn't get
  reassigned.
- *Commit messages* prefix the phase: =feat(insights): Phase 12.5 —
  engagement table=. Grep =git log --grep="Phase "= to find every
  phase landing.
- *Sub-phase numbering* is loose. 12.6 + 12.7 are reserved for
  planned work; if a 12.8 idea shows up first, it can take the
  next available number.
