* Summary

*Summary.* The /vault-hygiene team/ is the first =long-lived= team
canonized under [[id:1e75cdba-f743-456d-9d0f-07b9e0da33ac][multi-agent-org-llm]]: =@boothby= captains a
daily heartbeat (cron =0 8 * * *= EST proposed); =@geordi= drift-checks
tag taxonomy + freshness; =@atoz= audits cross-link health. Each role
runs in its own worktree on a shared =boardId=; per [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-006]] the
captain reads vault facts /deterministically/ before any LLM turn fires.
1-tick smoke ran live 2026-05-06 02:09 EDT — *PASS*, 63 s wall, $0.079
spend, both child sessions verified by =genealogy.parent_session_id=.

*Expanded.* This page documents what the team /shape/ is, what was
verified end-to-end today, and what gates the promotion from "1-tick
smoke" to "live daily cron." The team-shape — captain pre-fetches +
single LLM narration + sibling-spawn over MCP + captain's-log bridge
— held cleanly in 63 s for under eight cents. Two primitives the
production cadence needs are *not* yet on the harness: a =mcp_token=
refresh hook (24 h JWT expiry will halt heartbeat day 2) and the
=mode:"btw"= async peer-query primitive (today's smoke uses two
parallel spawns; richer mid-tick coordination wants =btw=). Both
filed below as gating follow-ups.

The board is the team's collaboration registry — sibling-discovery
is "list sessions on my =boardId=" rather than a separate registry.
Per [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-011]] the worktree filesystem (Agor's =LibSQL= backing) is /not/
authoritative for vault content; =~/org/*.org= remains canonical.
Children of the heartbeat run their own worktrees by default — the
smoke pre-creates them so per-tick worktree-create cost can be
amortised; in production each tick can either reuse worktrees
(cheap, faster) or recreate (clean slate, slower).

* Gating follow-ups

*Summary.* Two primitives are needed before promoting to a daily
cron, and a third smaller item surfaced in the smoke. Listed
captured-not-built; Agent A in this dispatch owns the harness work.

** Token refresh — *CLOSED 2026-05-06*

The captain's =mcp_token= is a 24 h JWT (per [[id:4e05d9b8-9399-4e88-9409-11dfe9cf390a][agor-smoke-recipe]]
step 6). Originally filed as a blocker because a daily cron at =0 8=
would hit expiry on day 2. /Now resolved./ =scripts/agor-token-refresh.sh=
(see [[id:4e05d9b8-9399-4e88-9409-11dfe9cf390a][agor-smoke-recipe]] § v0.2) implements route (b) — Agor's
after-=GET /sessions/:id= hook re-mints =mcp_token= with a fresh =exp=
claim, verified live (9/9 tests PASS). Heartbeat callers should call
=agor_refresh_if_near_expiry "$SID" "$current_jwt" 300= each tick to
amortise the round-trip; long-lived captain *sessions* now persist
across 24 h boundaries with token rotation handled inline.

** =mode:"btw"= async peer query (BLOCKING for richer coordination)

Today's smoke spawns =@geordi= and =@atoz= as independent children;
no mid-tick coordination. The richer pattern — =@atoz= asking
=@geordi= "is this drift signal already in your sweep?" without
either halting — wants =agor_sessions_prompt(mode:"btw")=. Per
[[id:4e05d9b8-9399-4e88-9409-11dfe9cf390a][agor-smoke-recipe]] § What this validates / leaves open, =btw= is
unverified in v0.17.3. Validating it is also Agent A territory.

** Inferrer sentinel surfacing (smaller; tracker fodder)

The =vault_profile_digest= reported =-1 nodes indexed= during the
smoke — a sentinel value from the org-roam node-count probe that
should be either non-negative or absent. The captain narrated this
correctly ("the org-roam graph can't yet validate any of those
links"), proving the team-shape /surfaces/ inferrer bugs as drift
signals. File the underlying probe fix as a tracker entry; the team
itself behaved correctly.

* Verdict

*Summary.* The 1-tick smoke proves the team-shape can hold across
heartbeats /within a single 24 h JWT window/. It does *not* prove
multi-day persistence — that gates on the token-refresh primitive.

*Expanded.* What the smoke validated: (1) three roles on one
=boardId= with one worktree each is a workable topology; (2) the
captain pre-fetch + single narration call pattern fits in <30 s and
<$0.10; (3) sibling spawns return verifiable =genealogy.parent=
edges; (4) the captain's-log bridge writes a clean
=kind=team-session= record; (5) the read-only constraint can be
enforced by prompt construction alone (no file writes occurred).
What the smoke did *not* validate: (a) day-2 heartbeat after JWT
expiry; (b) =btw= mid-tick peer query; (c) multi-tick captain
session reuse vs. recreate-per-tick. Verdict: *team-shape PASS,
multi-tick durability PENDING* — the gating items are scoped + filed,
not unknowns.
