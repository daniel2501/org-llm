* Summary

*Summary.* Sprint that validates the full org-llm + Agor stack
running cleanly on Termux + termux-x11 + sway. Per the verifier
(=/tmp/agor-mobile-termux-verify-2026-05-06.org=) the Agor daemon
is /plausibly/ installable on aarch64 Android — Node 22 LTS is
packaged, but =@libsql/client= ships glibc prebuilts that need a
=npm_config_libc=glibc= spoof under Bionic. User's experienced
termux take 2026-05-06: "promising"; default lean = native daemon
as primary path, canvas-only as fallback. /Goal of sprint:
validation, not feature-build./

*Expanded.* Mobile is a *peer device*, not a text-mode reduction
(per memory =project_mobile_is_full_graphical_emacs=). Termux +
termux-x11 + sway already runs Doom Emacs, xwidget-webkit, full
agent surfaces. What's *unverified* is whether Agor's daemon — the
substrate for [[id:1e75cdba-f743-456d-9d0f-07b9e0da33ac][multi-agent-org-llm]] team coordination — survives on
that stack. The verifier's evidence is structural ("Node 22 ships
on Termux" / "libsql has a glibc-spoof escape hatch") but no public
report of Agor specifically running on Termux exists. This sprint
closes that loop with on-device install + smoke + one spike-team
run. Mobile-org is an unachieved holy grail per memory
=project_mobile_org_holy_grail=; this work is /interface design on
a working substrate/, not a port — different knobs, different
interface, same agents.

* Mission

Verify the full org-llm + Agor stack runs cleanly on the user's
existing mobile Doom setup. Three validation gates:

1. *org-llm itself* boots and =org-llm doctor= comes back clean
2. *Agor daemon* installs + initializes + accepts smoke harness
3. *One spike-team run* (license-decision-shaped or smaller) completes end-to-end on the phone alone

Mobile is a peer device. The sprint doesn't try to replicate the
desktop flow — it captures /what's different/ (interface notes,
ergonomic deltas, knobs that need to differ) for a follow-on
interface-design pass.

* Stage 1 — org-llm bare-bones install on Termux

Bring org-llm itself up; verify =org-llm doctor= runs. Expect some
failures — bash-flavor differences, missing system tools (e.g.
=dbus=, =libnotify=), Termux-specific PATH quirks. /Failures here
are data, not blockers./

#+begin_src sh
cd ~/repos/org-llm
uv sync
uv run org-llm doctor          # capture full output
uv run org-llm --help          # verify CLI surface visible
uv run pytest -x -q            # full suite; document red lines
#+end_src

Document each failure under § Risks below as it surfaces. Common
suspects: bash-strict-mode hangs, =psutil= probes that assume
desktop /proc layout, =org-roam= DB path expectations.

* Stage 2 — Agor daemon install

Apply the agor-pilot-install pipeline (per [[id:9dc47d5a-5efe-4a04-8a3a-45b69643e982][agor-pilot-install.org]])
adapted for Termux — user-scope npm, glibc-spoof on libsql.

#+begin_src sh
pkg install nodejs git
node --version                                 # ≥ 22.12

# user-scope npm prefix
npm config set prefix ~/.npm-global
mkdir -p ~/.npm-global/bin
# add to ~/.bashrc / ~/.config/fish/conf.d/:
#   export PATH="$HOME/.npm-global/bin:$PATH"

# glibc-spoof per verifier
export npm_config_platform=linux
export npm_config_libc=glibc

npm install -g agor-live
agor --version                                 # → 0.17.3 hopefully
echo "n" | agor init --force
agor daemon start
curl -s http://localhost:3030/health           # → 200 hopefully
#+end_src

Document failures under § Risks. Most likely break-points: (a)
=@libsql/client= post-install probe under Bionic; (b) =better-sqlite3=
transitive build (clang on Termux ≠ standard); (c) port :3030
already in use; (d) daemon crashes on first session-create due to
filesystem-permissions issue.

* Stage 3 — Smoke harness on-device

Rotate the default admin password before any spawn (per
=agor-pilot-install.org= BUG-4):

#+begin_src sh
# rotate admin per pass-store
NEW_PW=$(pass org-llm/agor/admin-password)
# direct sqlite UPDATE per BUG-5 workaround until /users PATCH works
sqlite3 ~/.agor/agor.db \
  "UPDATE users SET password='$(node -e 'console.log(require("bcryptjs").hashSync(process.argv[1],10))' "$NEW_PW")' \
   WHERE email='admin@agor.live';"

agor auth login -e admin@agor.live -p "$NEW_PW"
agor repo add-local ~/repos/org-llm

bash scripts/agor-smoke.sh                     # green/red?
SKIP_CLAUDE=1 bash scripts/agor-smoke.sh       # REST primitives only
#+end_src

Log the green/red. Compare against desktop run from
=docs/wiki/agor-smoke-recipe.org=. Note any timing differences
(Termux clang-built libs may be slower than Guix prebuilts).

* Stage 4 — Interface-design notes

Per memory =project_mobile_org_holy_grail=, mobile needs different
knobs + interface, not just a port. Capture observations as the
sprint runs:

- *Input ergonomics.* Soft keyboard vs. Bluetooth vs. external — does =@<agent>= prefix friction differ?
- *Frame topology.* Single full-screen frame vs. desktop's split-pane — sidebar widget needs?
- *Notification model.* Termux notifications vs. Doom inline — where do agent responses land most ergonomically?
- *Capture latency.* Voice → org-capture → vault — is the chain fast enough that the user reaches for it instead of the messaging app?
- *Daemon visibility.* Is the user aware Agor is running? Should there be a status-bar widget?
- *Battery feel.* After 1 hour of use, what does the battery cost?
- *Offline shape.* What still works with no network? (Should be: vault edits, agent prefetch, deterministic tools.)

These notes feed a follow-on /mobile interface design/ work item —
*not part of this sprint's exit criteria*.

* Risks / Known gotchas

| Risk                                                          | Likelihood | Mitigation / Detection                                                    |
|---------------------------------------------------------------+------------+---------------------------------------------------------------------------|
| Doze + battery management kills daemon overnight              | High       | Termux:Boot + wakelock; "Battery Unrestricted" toggle per OEM             |
| Bionic libc vs. glibc — =@libsql/client= post-install crash   | Medium     | =npm_config_libc=glibc= spoof per verifier; fall back to canvas-only      |
| =better-sqlite3= source build fails on Termux clang           | Medium     | Drizzle uses libsql primarily; check transitive deps before installing    |
| Storage permissions — Termux can't read =~/org/=              | Low-Med    | =termux-setup-storage=; symlink =~/org → /storage/emulated/0/org=         |
| Multi-process contention (Node daemon + Emacs + sway)         | Low        | OOM-killer on 6GB devices; monitor; document RAM ceiling                  |
| xwidget-webkit availability inside Termux Emacs               | Unknown    | Test early — needed for Agor canvas viewer fallback                       |
| Port :3030 collision with another mobile dev tool             | Low        | =AGOR_PORT= override; document chosen port                                |
| =agor init= prompt is interactive (Termux terminal quirks)    | Low        | =echo "n" \| agor init --force= per pilot-install                         |
| /proc layout differences break psutil probes                  | Medium     | =org-llm doctor= will surface; capture, don't fix unless blocking         |
| Daemon-crash on backgrounded Termux                           | Med-High   | Wakelock + Termux:Boot; if still flaky → cron-style health-check restart  |

* Sprint exit criteria

Sprint is *DONE* when all three are true:

1. =org-llm doctor= returns clean (or only documented-acceptable warnings) on the phone
2. =bash scripts/agor-smoke.sh= returns green on the phone
3. *One spike-team run* — any minimal multi-agent dispatch (e.g. a 2-child investigation) — completes end-to-end on the phone alone, with verified =genealogy.parent_session_id= edges and a captain's-log entry written

Anything beyond those three is bonus. Specifically /not/ in scope:
mobile-specific UI work, sidebar redesign, notification integration,
multi-agent canvas tuning. Those are follow-ons.
