** [A 2026-05-08 02:00] R18 v1 KILLED — provider-pin tool-format issue

After 5 min / 96 cells, leaderboard showed catastrophic silent_noop
pattern on K7/K8/K17/K15/K5 (all score=0, cost=0). Diagnosis of K8
cell: text_output =\"I'll make exactly 5 cross-link edits ...
Here are the function calls:\n\n\"= but =tool_calls=0=, =finish_reason=null=.
Model announced tool calls then stopped — *DeepInfra doesn't support
OpenAI tool-format for deepseek-chat-v3*. With =allow_fallbacks: False=,
no recovery route → silent cell. Identical pattern likely affects
K7-qwen72b on DeepInfra and K17-glm46 on SiliconFlow.

*Root cause.* R18's "tighten provider pins" addition went too far.
R17's =allow_fallbacks= default True ("advisory pin") was the working
config — pins were a preference, not a hard constraint. Adding
=allow_fallbacks: False= made the bad pin combinations FAIL instead
of silently fallback-recover.

*Fix applied.* Reverted =allow_fallbacks: False= from all PROVIDER_PINS
entries. Kept the broker remap (preferred-first ordering). Pins are
now advisory again — the R17 working behavior.

*Trade-off.* Loses some cache-hit predictability (R17 measured 14.6%
realized vs 22-27% predicted). Gains: tools actually work for K7/K8/K17.
Net: better data > better caching at this stage.

R18 v2 launching now.
