the K1+K8 FOSS frontier holds, K8-deepseekV3 fully recovered from
its R19 collapse (164/25 cells), and K7-qwen72b deserves a

to a harness mis-categorization of target_files as out-of-scope.

gradually catching up to the strategy. R18 wiped 64% of cells via
worktree races (fixed in fc59d1c). R19 had the right strategy
(BK1-BK5 wired) but the long-horizon tasks never selected (fixed
in R24 with Layer-BK). R24 has BK1-BK5 firing but every cell
scores zero because of the target_files bug. The pattern: each
round's headline finding is itself a bug that the next round
exposes. R25's prep MUST fix the two bugs above plus extend
WALL_CAP enforcement (the constant exists but is not enforced;
one K2 cell ran 1612s holding Layer 1 open for 9 min).

* Bench-correctness bugs (R25 BLOCKERS)

** Bug 1 — quality_lint nested-bracket detector multi-line FP

*Discovered by:* R24 quality-judge agent.

*Mechanism.* =count_nested_bracket_depth= walks only =+= lines.
A multi-line org link like:

#+begin_src text
+ - See [[id:abc][some
   long display text spanning
   lines]]
#+end_src

gets concatenated to:

#+begin_src text
- See [[id:abc][some
  long display text spanning
#+end_src

(closing =]]= is on a context line, dropped). Cursor sees =[[=
without =]]= → depth 1, never reset. A subsequent well-formed
=[[id:UUID][label]]= on the next added line registers as
"depth=2" → false-positive nested_bracket count.

*Blast radius.* ~190 of the 234 lint-penalty points assigned to
K1-qwen30 + K11-qwen3coder in R24 are FPs. K1's "real" adjusted
score is 32.22 not 23.72. Leaderboard rank ordering is mostly
preserved (K1 still #1 corrected) but score magnitudes are
under-reported.

*Fix shipped.* =count_nested_bracket_depth= now scans each line
independently — depth resets per line. Catches within-line
cascades (R18 K6/K7 archetype) but doesn't propagate ghosts.
File: =scripts/quality_lint.py=.

** Bug 2 — BK long-horizon cells primary=0 due to target_files

*Discovered by:* R24 quality-judge agent.

*Mechanism.* =analyze_diff= categorizes each diff hunk as in-scope
or out-of-scope based on the task's =target_files= list. The
=_round19_long_horizon_tasks.py= fixtures (BK1-BK5) define
=target_files= as test-fixture paths only, not the actual
implementation paths the task asks the model to edit. Result:
every BK cell's edits land in "out-of-scope" buckets, primary
metric = 0, score = 0 regardless of actual edit quality.

*Verified separately.* Hand-inspection of BK1 (rename refactor),
BK2 (typer subcommand + test), BK4 (dataclass + schema), BK5 (11
wrap-edits) shows working clean implementations on disk in the
worktrees. The MODEL did the work; the HARNESS failed to credit it.

*Blast radius.* All 10 BK cells (~30 min wall, ~$3 spend)
produced no usable signal. The "BK1-BK5 long-horizon FOSS-vs-
Claude question" remains *unanswered* by R24.

*Fix needed for R25.* Update =scripts/_round19_long_horizon_tasks.py=
to populate =target_files= with the ACTUAL implementation paths
each BK task touches:

| Task | target_files needs                                                 |
|------+--------------------------------------------------------------------|
| BK1  | =org_llm/specialist.py=, =scripts/_round{20,21,22,23,24}_dials.py= |
| BK2  | =org_llm/cli_specialist.py=, plus the new test file path           |
| BK3  | =org_llm/specialist.py= (the failing test injection lives here)    |
| BK4  | =org_llm/specialist.py=, =scripts/specialist_schema.json=          |
| BK5  | 5 wiki/notes pages cited by BK fixture                             |

Plus: verify =analyze_diff= treats those paths as "in scope" by
default. Per-task allow-list works.

* Wall time + parallelism reality check

** R24 wall = 54.3 min, NOT 22 min

The "22 min" we'd been quoting was the timestamp of R24's first
stdout LEADERBOARD print. Round actually ran 54.3 min total.
Walltime agent measured: log timestamps 08:19:42 → 09:14:02 =
3260s.

** Doubling workers 16→32 made wall WORSE

R18 (16 workers, 140 cells, ~28 min) → R24 (32 workers, 147 cells,
~54 min). Why:
- Layer 1 sample-up scaled from 80 cells to 115 cells (more n
  on K1/K2/K8) → sum-of-walls grew ~7.4×
- Workers grew only 2× → backlog
- =WALL_CAP_PER_CELL_S=400= was added as a constant but never
  enforced at runtime
- One K2-kimi-k2.6 cell ran *1612s (27 min)* alone, holding
  Layer 1 open for the final 9 min

** K7 owns 5/10 of round's longest cells

K7 sum-of-walls = 5594s (mean 559s/cell). Drop K7 (Sp4) saves
~930s of R25 wall. Highest-impact speedup per agent ranking.

** Layer-BK was actually FAST

Layer-BK ran 10 cells in 157s (mean 16s/cell) — much faster than
R25 design's projection of 15-25 min. Long-horizon is NOT the
wall risk we expected. The slow cells are big-prose B11 + B5,
not multi-file BK.
