* Summary

*Summary.* The durable record of *directional* decisions for
org-llm — the choices a future contributor (human or agent)
would otherwise have to reverse-engineer from commits. One
heading per decision, with =:ID:= for org-roam linking, status,
date, context, decision, and consequences. Not every choice
goes here; only the ones that would surprise a future reader
or that we'd hate to re-litigate.

* Summary of when to write one

*Summary.* Write a decision entry when the choice is
*directional* (sets a default for future work), *non-obvious*
(a smart contributor would otherwise pick differently), or
*paid for* (we tried the alternative and it cost us). Skip
decisions that are obvious from the code, locally scoped, or
trivially reversible. If unsure: ask in
[[id:32f134ee-dc89-41a0-9a7b-930a7cad452a][captain's log]]
whether the decision belongs here, then either write the
entry or drop the question.

*Expanded.*

Triggers (write an entry):
- A new convention every contributor will need to follow
  ("the wiki is org, .md is for cross-tool surfaces only")
- Closing off an alternative we evaluated and rejected
  ("we considered libSQL; staying on SQLite because …")
- A trade-off where the loser is non-obvious
  ("vault-authoritative now → DB-authoritative in Phase 25;
  the inversion has costs and we accept them because …")
- A deferral with a trigger condition
  ("CODEOWNERS deferred until N agent reviewers …")

Anti-triggers (skip):
- The choice is visible in code or wiki and self-explanatory
- The choice is local to one file/function
- The choice will be reversed cheaply if wrong
- The choice is "use library X" with no real alternative

When in doubt, lean toward writing — a 5-line entry is cheap;
re-litigating a forgotten decision is expensive.

* Convention

Each decision is a level-1 heading with this shape:

#+begin_example
* DEC-NNN — short title
:PROPERTIES:
:ID:       <uuid>
:STATUS:   accepted | superseded-by-DEC-MMM | deprecated
:DATE:     [YYYY-MM-DD]
:DECIDERS: <names / instance handles>
:END:

*Summary.* One-paragraph TL;DR (per wiki Rule 2b).

*Context.* What forces are at play. What we knew at the time.

*Decision.* What we decided.

*Consequences.* What this commits us to. What it forecloses.
What might trigger revisiting.
#+end_example

Numbering: =DEC-NNN= is monotonic, three digits, never reused.
Superseded entries stay in place with =STATUS: superseded-by-X=
and a link to the successor — don't delete history.

The seed entries below establish the format. Future decisions
append at the end of the "Decisions" section.

* Decisions

** DEC-001 — Branching: trunk model with PR-to-main
:PROPERTIES:
:ID:       1f3eaffe-3edd-4d8f-9aa7-9aa9c5e35d9e
:STATUS:   accepted
:DATE:     [2026-05-04]
:DECIDERS: Daniel, Claude/opus-A
:END:

*Summary.* Primary integration is on the =trunk= branch;
everything merges to =main= via PR. Secondary streams
(human or agent) branch off =main= using the
=<who>/<slug>= naming scheme. =main= is protected; force-push
forbidden. Force-push to =trunk= requires a captain's-log
announcement.

*Context.* org-llm went from one developer to a parallel
human + agent team in May 2026. Without an explicit branching
model, instances were defaulting to direct =trunk= edits —
fine for one developer, breaks immediately at N>1.

*Decision.* Trunk-based development with PR-mediated merges to
=main=. =trunk= is the primary stream's working branch (the
maintainer's local-fast-path); secondary streams use named
branches off =main=. PRs target =main=, not =trunk=.

*Consequences.*
- All non-primary work is reviewable before merge.
- The maintainer's =trunk= velocity is unchanged.
- Force-push hygiene becomes a coordination signal (forbidden
  on =main=, announced on =trunk=, free on personal branches).
- Triggers revisit: if N humans regularly merge directly,
  collapse =trunk= into =main= and use only named branches.

** DEC-002 — Org-native first; .md only for cross-tool surfaces
:PROPERTIES:
:ID:       4a2ffd67-2ddc-4d12-9b18-86e7e15ec6a4
:STATUS:   accepted
:DATE:     [2026-05-04]
:DECIDERS: Daniel, Claude/opus-A
:END:

*Summary.* All durable project documentation lives in
=docs/wiki/= as =.org= files with =:ID:= properties for
org-roam linking. Markdown files are reserved for surfaces
that external tools auto-load and don't render =.org= well:
README.md (GitHub front page), CONTRIBUTING.md or .org (TBD),
AGENTS.md (cross-tool agent primer), .github/* templates.

*Context.* org-llm is "Claude Code for Org Mode" — the
file format IS the brand. But GitHub, Claude Code, opencode,
and Cursor all auto-discover certain =.md= filenames. Forcing
=.org= everywhere would lose those integrations; forcing
=.md= everywhere would lose org-roam graph + Emacs ergonomics.

*Decision.* Org is the default. =.md= is the exception, used
only where a cross-tool surface specifically requires it.
Every =.md= file at root or in =.github/= should link back
into the org wiki for the substantive content.

*Consequences.*
- The wiki concept graph stays whole.
- New contributors landing on README/CONTRIBUTING get a hop
  into the org wiki, not a separate .md tree.
- Updates: any concept page change ripples to the .md
  surfaces that reference it (per
  =feedback_keep_wiki_and_readme_in_sync=).
- Triggers revisit: if a tool we adopt only reads .org, we
  drop the corresponding .md.

** DEC-003 — Agents-as-SDLC; vault is substrate
:PROPERTIES:
:ID:       8e0c3b71-1f75-4a0f-9d3e-9b85f29c4ed1
:STATUS:   accepted
:DATE:     [2026-05-04]
:DECIDERS: Daniel, Claude/opus-A
:END:

*Summary.* org-llm's stance on SDLC for code projects (its own
or users') is: org-mode is the substrate (headings, properties,
agenda, clock, priorities, roam-links provide most of the data
layer "for free"); agents are the SDLC layer (judgment,
facilitation, cross-document synthesis, ceremony when
configured). Formality is a configuration knob
(=sdlc.formality = none | light | kanban | scrum=), not
separate products. The "none" level must stay genuinely free
of nags.

*Context.* The team going multi-developer raised the question
of formal SDLC. The org-llm thesis ("Claude Code for Org
Mode", agent-driven life management) means SDLC for code is
already in scope as a specialization, not a pivot. The risk
is generalizing too early into a Linear/Jira-shaped product
surface before we know what's load-bearing.

*Decision.*
1. Dogfood SDLC on org-llm itself first; do not generalize.
2. Use existing agents (=@curator=, =@tracker=) for
   PM-shaped work; promote new agents (=@scrummaster=,
   =@projectmanager=, etc.) only when patterns are
   undeniable, per agent-idea-interaction-lens and Phase 29
   self-coded-tools.
3. Treat ceremony as opt-in, never as default.
4. Differentiator must be agent-native + vault-grounded +
   org-native; do NOT pursue feature-parity with Linear/Jira.

*Consequences.*
- The Phase-29-and-later roadmap gains an "SDLC arc"
  candidate (not yet committed; see
  [[id:43e1b335-656b-45ba-8d6d-7d9b9f2e9c4d][roadmap]]).
- Decision blocks attempts to add cross-project PM features
  before single-project dogfooding has shipped.
- We accept that the upper end of the formality spectrum
  (full Scrum) is *designed*, not *dogfooded*, until org-llm
  has a real multi-team user.

** DEC-004 — CODEOWNERS deferred; trigger is non-human reviewers
:PROPERTIES:
:ID:       db61ab07-3475-4cda-9b58-f3e1cdc3af2a
:STATUS:   accepted
:DATE:     [2026-05-04]
:DECIDERS: Daniel, Claude/opus-A
:END:

*Summary.* No CODEOWNERS file at this stage. Revisit when there
are enough *non-human* reviewers regularly approving merges
that owner-routing would route review labor in a meaningful
way; revisit also if/when the human team grows past ~3
regular committers. Today the human/agent count makes
CODEOWNERS premature ceremony.

*Context.* The user explicitly framed CODEOWNERS as
applicable "once we get enough NON humans merging" — the
forward-looking framing is that agents will be normal
reviewers, and CODEOWNERS becomes meaningful when routing
a PR to =@curator= or =@tracker= for wiki / dev-process
review actually delegates labor. Today the team is one
human + a handful of in-conversation agents; routing has no
work to amortize.

*Decision.* Skip CODEOWNERS for now. The trigger to add it
is *either*:
- ≥3 regular human committers (review-load distribution
  becomes a real concern), *or*
- ≥2 stable agent reviewers wired into PR review
  (programmatic delegation to =@curator=, =@tracker=, etc.)

*Consequences.*
- Today: no review-routing ceremony to maintain.
- Future: when triggered, the file's first ownership lines
  will likely route =docs/wiki/*= → =@curator=,
  =org_llm/dev_tracker_*= → =@tracker=,
  [[file:../../org_llm/llm_proxy.py][=org_llm/llm_proxy.py=]] → maintainer, etc. — i.e., agent
  ownership of the surfaces those agents already steward.
- This decision is part of the
  "agents-as-SDLC" thesis (DEC-003); CODEOWNERS is a
  natural artifact of that thesis once non-human reviewers
  stabilize.

** DEC-005 — Strict claim-before-touch + commit hygiene + worktree escape hatch
:PROPERTIES:
:ID:       54843097-3bf9-447e-b8b8-54cbc0a0ed6b
:STATUS:   accepted
:DATE:     [2026-05-04]
:DECIDERS: Daniel, Claude/opus-B
:END:

*Summary.* The unified git strategy for org-llm. Builds on
DEC-001 (trunk + PR-to-main) by adding three operational rules:
*claim-before-touch is strict for everyone including the
maintainer*; *commit hygiene* (pull-rebase before push, explicit
file staging, =scope = phase= in conventional-commits format,
push immediately after commit); and a *worktree escape hatch*
when concurrent agents physically overlap on hot files. The
strict claim closes a loophole that ran silently across 414
solo-maintainer commits — fine at n=1, breaks at N≥2.

*Context.* On 2026-05-04 the project went from one
solo-maintainer to a parallel human + agent team (multiple
Claude Code / opencode instances, future @-agents). That same
day three commits landed in trunk in six minutes from different
agents (=docs(wiki):= → =feat(resolvers):= → =feat(primers):=)
with overlapping uncommitted edits to =orchestration.py= /
=mcp_server.py= / =db.py=. The existing
[[id:03be52bf-003f-4762-a274-e7c88f97847f][coordination.org]] Rule 1
already requires a claim before any =Edit=/=Write=, but n=1
muscle memory has been running without one — the rule reads
strict but operates soft. This decision flips it operationally.

The git log itself is evidence the existing flow works: 414
commits, zero merge commits, zero abandoned branches,
conventional-commits format strictly followed, every commit's
scope tied to a phase. The strategy preserves that velocity for
the maintainer's primary stream while adding the minimum
ceremony needed for parallel work.

*Decision.*

1. *Strict claim-before-touch — no maintainer exception.* Every
   contributor (human or agent) opens an =active-claims.org=
   STARTED heading before the first =Edit=/=Write= in a session.
   This applies to Daniel's solo sessions too. The license to
   skip the claim board ended on 2026-05-04 when N became ≥2.

2. *Commit hygiene rules.*
   - Stage files explicitly (=git add <path>=); never =-A= /
     =.= / =-u=. The git-safety-protocol bans this; DEC-005
     promotes it from agent-instruction to project rule.
   - =git pull --rebase= before =git push=. Concurrent commits
     resolve as fast-forwards or interleaves, never merges.
     The trunk graph stays linear (zero merge commits across
     414 commits is a feature; preserve it).
   - Conventional Commits with =scope = phase= (or
     =scope = component= when phase doesn't apply):
     =feat(primers): Phase 24.5b — …=,
     =docs(wiki): canonize agent-orientation pattern + …=.
     The scope token grep-anchors the phase narrative.
   - Push immediately after commit. Holding committed-but-
     unpushed work is a coordination violation when other
     agents are active — they can't pull-rebase against work
     they can't see.
   - Co-author tag stays for agent commits:
     =Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>=
     (or equivalent for other agents). Preserves attribution
     lineage even when squashed/rebased.

3. *Worktree escape hatch.* When your planned scope overlaps a
   hot file (=orchestration.py=, =mcp_server.py=, =db.py=,
   =cli.py=, =llm_proxy.py=) that another contributor has
   uncommitted local changes on, you MUST either:
   - Coordinate via captain's log (=kind=coord=) and wait, OR
   - Spin up =git worktree add ../org-llm-<phase> origin/main=
     (or =origin/trunk= if you're on the maintainer's stream)
     and work there. The worktree shares =.git= with the main
     checkout — no clone, no remote-config drift; just a
     separate working dir for a separate branch.
   The list of "hot files" is the set the dev-tracker phase
   plans repeatedly schedule for edits; today's set is the
   five named above. Add to it (in this DEC) when a sixth
   surfaces.

4. *No PR gate until the trigger.* PRs to =main= remain the
   merge surface for secondary streams (DEC-001), but no CI
   gating, no required review, no PR template enforcement
   beyond what =.github/PULL_REQUEST_TEMPLATE.md= proposes.
   Trigger to add a CI gate: ≥3 regular human committers OR
   the first outside FOSS contributor (whichever is first),
   matching DEC-004's CODEOWNERS trigger.

*Consequences.*
- *Operational.* Daniel's solo sessions now post a claim before
  editing. Cost: ~30 seconds per session start. Benefit: agents
  spawning concurrently can see what's in flight without
  guessing from =git status=.
- *Velocity.* The maintainer's trunk fast-path is preserved
  (DEC-001 unchanged). Pull-rebase and explicit staging are
  habit-shaped friction that surfaces races loudly rather than
  letting them silently corrupt the working tree.
- *Worktree escape hatch.* Lets parallel agents proceed when
  they would otherwise have to wait for someone else's commit.
  The maintainer rarely needs it; secondary streams reach for
  it whenever DEC-001 would otherwise force them to coordinate
  before starting.
- *Forecloses.* No long-running feature branches that miss
  trunk by weeks. No squash-rebase-rewrite of public history.
  No CI ceremony before it amortizes. No "I'll claim later"
  escape valve.
- *Triggers revisit.* If we reach ≥3 regular human committers
  or first outside contributor, add CI + required review (and
  re-evaluate CODEOWNERS per DEC-004). If hot-file races
  recur despite the escape hatch, escalate the file to
  per-section locks or split it.

** DEC-006 — Supervision is deterministic by default
:PROPERTIES:
:ID:       cf17c89e-2a9e-46b0-9e3f-7c44d6f1bd92
:STATUS:   accepted
:DATE:     [2026-05-04]
:DECIDERS: Daniel, Claude/opus-C
:END:

*Summary.* When the agent layer needs supervision —
disambiguating a prompt, recovering from a wrong tool call,
spotting a confusion loop — that supervision runs as
*deterministic code* unless the confusion genuinely requires
reasoning. An LLM-based observer is an extra round-trip per
turn and the orchestration top priority (smoother + faster +
higher-quality than solo) fails the moment supervision taxes
latency. Sharply: /if a confusion can be detected by code, it
must be; LLM-based supervision is reserved for confusions that
genuinely need reasoning./ Implemented as the Phase 24
[[id:43e1b335-656b-45ba-8d6d-7d9b9f2e9c4d][supervision trinity]] —
three registries (pre-flight resolvers, tool-failure recovery
hooks, confusion detector) that each accept new entries the
way the recipe registry accepts new recipes.

*Context.* The 2026-05-04 =@curator= bug surfaced the gap:
user said "@curator in org-llm, =wiki/superset.org=, fix it
up"; agent looked in cwd then =~/org/=, gave up. The actual
file was =docs/wiki/superset.org= in the repo. The user
asked for a generalizable fix — manager spotting the problem
without taxing speed — and pushed back on bandaiding the
specific path-resolution case. The conversation surfaced the
broader rule: pattern-matchable confusions are code's job;
reasoning-required confusions are the LLM's. Most agent
confusion is pattern-matchable.

*Decision.*

1. *Default mode is deterministic.* Pre-flight enrichment,
   recovery hooks, and confusion detection all run as pure
   code in registry-shaped modules. Adding a new resolver /
   hook / signal is one entry, not core surgery.

2. *LLM-based supervision is the exception.* Reserved for
   confusions that genuinely need reasoning — semantic
   equivalence judgments, cross-phrasing intent matching,
   subjective output quality. When invoked, prefer
   /async/off-the-critical-path/ shapes (manager quorum
   reviewing the audit log retrospectively) over inline
   round-trips.

3. *The trinity is the implementation surface.* Phase 24
   ships three registries: 24.1 pre-flight resolvers, 24.2
   tool-failure recovery hooks, 24.3 confusion detector
   (24.4 manager quorum is the open-question slot for the
   exception case, async-only). Future supervision needs
   choose which registry to extend, not whether to spin a
   new layer.

*Consequences.*
- Architecture rule canonized in
  =docs/wiki/architecture.org= § /Design rule —
  supervision is deterministic by default/.
- Phase 24 trinity is the load-bearing surface;
  later phases (29 self-coded tools, 30 FOSS agent value-adds)
  treat the registries as the auto-promotion targets.
- Forecloses LLM-observer-per-turn shapes — those
  break the orchestration top priority and won't ship.
- Triggers revisit: if a class of confusion proves
  /unambiguously/ to need reasoning AND can't tolerate async,
  add a 4th registry slot (with the same shape) rather than
  abandoning the rule.

** DEC-007 — Wiki Rule 2b: every concept entry is Summary + Expanded
:PROPERTIES:
:ID:       7be1d9c4-4f50-4f6b-bbf8-69152f3a68a4
:STATUS:   accepted
:DATE:     [2026-05-04]
:DECIDERS: Daniel, Claude/opus-C
:END:

*Summary.* Every new concept, design rule, or architectural
decision in the wiki must lead with a =*Summary.*= paragraph
(1–3 sentences, the load-bearing claim) followed by
=*Expanded.*= prose. Both, every time. Not just one. Canonized
as Rule 2b in
[[id:d30c177e-5b09-4f52-95bf-bb2d36f663e8][wiki conventions]].

*Context.* Every wiki concept is read at two speeds: by a
future LLM/human looking up one fact (wants the summary), and
by someone learning the system (wants the full context). The
status quo (single prose section) buried the load-bearing
sentence inside the body, costing both audiences. Forcing the
author to write both up-front means the summary actually
exists and isn't just the first paragraph by accident.

*Decision.* Triggers (require both blocks): new design rule,
new top-level architecture section, new recipe / agent / tool
getting its own wiki page, substantial revision of an
existing concept page. Anti-triggers (one block fine): typo
fixes, link repairs, passing edits.

*Consequences.*
- Author cost: writing the summary forces clarification of
  the load-bearing claim. Five extra minutes; cheap.
- Reader cost: the summary covers ~80% of lookup needs in
  ~10% of the page; the rest stays available.
- The supervision rule (DEC-006) was the worked example of
  this convention applied to itself.
- Triggers revisit: if the summary/expanded split feels
  redundant on small pages, allow Summary-only on entries
  under ~150 words. Today's call: keep the rule strict
  to build the habit.

** DEC-008 — Phase 24.1 wires at the @-prefix seam, not delegate-only
:PROPERTIES:
:ID:       8aa9e7d2-9f63-4ef3-9b25-3b1c7d2e8f5a
:STATUS:   accepted
:DATE:     [2026-05-04]
:DECIDERS: Daniel, Claude/opus-C
:END:

*Summary.* The pre-flight resolver enrichment fires inside
=intercept_agent_prefix= in [[file:../../org_llm/llm_proxy.py][=org_llm/llm_proxy.py=]] (the
@-prefix persona-swap seam), not only inside =delegate()=
in [[file:../../org_llm/mcp_server.py][=mcp_server.py=]]. The
=delegate()= wiring stays as a defensive belt-and-suspenders
for programmatic delegate calls; the proxy wiring is the
load-bearing path because every @-prefix-routed turn flows
through it. Eager-imports =org_llm.resolvers= at proxy
module-load time so the prewarm thread is finished before
the first user prompt and the cold-start budget never bites.

*Context.* The first cut of Phase 24.1 wired the resolver
into =delegate()= only. Live verify against the motivating
=@curator/superset.org= bug failed to fire enrichment because
curator (running on cloud =qwen-2.5-72b= via the @-prefix
swap) called tools directly without going through
=delegate()=. The =manager-log.jsonl= was empty; my resolver
never ran. Reading
[[id:47ba2143-c53a-409a-8286-2b3759794608][llm-proxy.org]]
made the seam location obvious: =intercept_agent_prefix= (#6
in =DEFAULT_INTERCEPTORS=) is where every @-prefix turn gets
its persona swap, and the recipe pre-fetch (Phase 22 v2)
already mutates =agent_prompt= here. Resolver enrichment
slots in cleanly using the same pattern.

This is also the user's "don't bandaid" feedback applied:
wiring at =delegate()= solved a narrow case; the general
problem is "every agent dispatch deserves enrichment." The
@-prefix seam is that general dispatch surface.

*Decision.*

1. Resolver call moves to (or is duplicated in)
   =intercept_agent_prefix=, immediately after the recipe
   pre-fetch block, mutating =agent_prompt= the same way.
2. =delegate()= call site keeps its resolver call as a
   defensive layer for programmatic delegate invocations
   that don't traverse @-prefix.
3. =org_llm.resolvers= is eager-imported at module load
   in =llm_proxy.py= so =_prewarm_caches()= fires at proxy
   startup. First user prompt sees warm caches; the 80ms
   wall-clock budget stays comfortable.
4. The same wiring lesson applies forward: future Phase 24
   sub-phases (recovery hooks, confusion detector) wire at
   the *broadest dispatch seam available*, not the narrowest
   convenient call site. The trinity's value compounds when
   each layer hits every turn, not just manager-mediated
   ones.

*Consequences.*
- Phase 24.1 closes the motivating bug end-to-end via the
  @-prefix path; verified live (third turn of 2026-05-04
  session: agent's first tool call hit the absolute path).
- Resolver enrichment is now a shared seam with recipe
  pre-fetch; both mutate =agent_prompt= at the same site.
  Future contributors expecting ONE pre-flight surface get
  it.
- Sticky turns (=intercept_agent_sticky= prepends @<intent>)
  benefit transitively — sticky chains into agent_prefix and
  the resolver fires there.
- Pronoun-only follow-ups ("read it") still don't get path
  resolution because there's no token to extract. That's a
  separate enhancement (resolve from conversation history),
  noted but not in 24.1 scope.
- Forecloses the "wire at the most convenient site" lazy
  default. Future trinity work explicitly evaluates seam
  breadth before choosing wire-in.
- Triggers revisit: if pronoun-resolution becomes a recurring
  need, file as a 24.1.x sub-phase that pulls the last N
  user turns into the resolver's input.
