* Why this primitive matters

Per [[id:3a8b1f72-9c4d-4e21-a5d8-7b2e9f1c3a6d][long-lived-team-vault-hygiene.org]] § "Gating follow-ups", the
captain's =mcp_token= is a 24 h JWT. A daily cron at =0 8= would hit
expiry on day 2 — silently — without a refresh hook. Two paths were
on the table:

| Option | Strategy                                          | Tradeoff                                              |
|--------+---------------------------------------------------+-------------------------------------------------------|
| (a)    | Re-issue a fresh captain session every tick      | Loses per-session state; spawn cost; genealogy churn  |
| (b)    | Refresh token via =GET /sessions/:id= after-get hook | Captain *session* persists; only the *token* rotates  |

Path (b) was the recommendation in C's report. This build verified
the contract, codified the call shape, and made it callable from any
heartbeat script.

* Contract verification (pre-flight)

The premise — Agor's =GET /sessions/:id= regenerates =mcp_token= in
the response — was claimed in C's run report but not directly
verified. First action: confirm it.

#+begin_src sh
# Two GET calls 2 s apart against the same archived session
T1=$(curl … "/sessions/$SID" | jq -r .mcp_token)
sleep 2
T2=$(curl … "/sessions/$SID" | jq -r .mcp_token)
[[ "$T1" != "$T2" ]] && echo "TOKEN_DIFFERS=YES"
exp1=$(decode "$T1") ; exp2=$(decode "$T2")
echo "exp delta: $((exp2 - exp1)) s"
#+end_src

Result: =TOKEN_DIFFERS=YES=, =EXP_INCREASED=YES=, =delta = 2 s= (matches
sleep). The hook /always/ re-mints — there's no caching window. For
high-frequency callers this means it's worth gating refresh on a
threshold; for once-a-day heartbeat ticks, "refresh always" is fine.

* Primitive design

*Sourceable + standalone.* Bash, ~150 lines. Five public functions:

| Function                                     | Returns                                      | Use case                       |
|----------------------------------------------+----------------------------------------------+--------------------------------|
| =agor_decode_jwt_exp <jwt>=                 | exp epoch (positive int)                     | Diagnostics; debugging          |
| =agor_token_seconds_until_expiry <jwt>=     | int seconds (negative = expired)             | Monitoring                      |
| =agor_token_near_expiry <jwt> [thresh=300]= | exit 0 if near or past expiry                | Branching                       |
| =agor_refresh_session_token <sid>=          | fresh mcp_token JWT                          | Heartbeat re-mint               |
| =agor_refresh_if_near_expiry <sid> <jwt> [thresh]= | fresh JWT or current JWT unchanged    | Amortised heartbeat re-mint     |

*Standalone CLI* mirrors each function: =decode= / =seconds-left= /
=check= / =refresh= / =refresh-if-needed=.

*Defaults.* =AGOR_REFRESH_THRESHOLD_SECONDS=300= (5 min). For daily
heartbeats this is a reasonable margin; for sub-minute polling, lower
it to ~30 s; for "every tick refresh", call =agor_refresh_session_token=
directly.

*Exit codes.* Reuses the v0 harness's code space (=10 PREREQ=, =20
AUTH=, =30 NOTFOUND=, =35 NOMCP=, =40 USAGE=) so callers can branch
uniformly across the smoke + refresh primitives.

*No new dependencies.* =jq=, =curl=, =base64= only — same set the v0
harness already requires.

* Bug found en route (v0.17.3, addendum to recipe — bug #9)

*=GET /sessions/<bogus_id>= returns HTTP 500 with =GeneralError=
"Session not found: …" instead of a proper 404.* This is the second
"500 instead of correct status" pattern in v0.17.3 (the first was
=GET /sessions/:id/genealogy= which 500s on undefined params).

#+begin_quote
=BUG-09= — =GET /sessions/<unknown_id>= returns =HTTP 500= with body
=={"name":"GeneralError","message":"Session not found: <id>","code":500,"className":"general-error"}==.
A proper REST contract would return 404. Workaround in
=agor-token-refresh.sh:_atr_die path=: pattern-match
=message =~ /[Ss]ession not found/= on 500 responses and treat as
404 / NOTFOUND. Caller-side code stays clean; the daemon-side fix is
upstream.
#+end_quote

* Use from a heartbeat script

#+begin_src sh
# Source the library
. scripts/agor-token-refresh.sh

# Each tick, refresh the captain's token if it's within 5 min of expiry
# (otherwise pass through unchanged — amortises the round-trip)
captain_jwt=$(agor_refresh_if_near_expiry "$CAPTAIN_SID" "$captain_jwt" 300)

# Re-write the MCP config so claude -p / opencode pick up the new bearer
jq --arg auth "Bearer $captain_jwt" \
   '.mcpServers.agor.headers.Authorization = $auth' \
   "$MCP_CONFIG" > "$MCP_CONFIG.new" && mv "$MCP_CONFIG.new" "$MCP_CONFIG"

# Now spawn the heartbeat children — token will outlive the tick
# even on day 2 of a long-running cron
#+end_src

For sub-minute polling, drop the threshold:
=agor_refresh_if_near_expiry "$SID" "$jwt" 30=. For "every tick refresh
unconditionally", call =agor_refresh_session_token "$SID"= directly.
