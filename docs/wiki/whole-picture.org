* Summary

*Summary.* org-llm is /Claude Code for Org Mode/ — agent-driven life
management built as an opinionated FOSS-anti-capitalist distro on top
of Doom Emacs + opencode + a dbt-shaped data layer. The lead value
(β) is *dream-state vault via agents*; α is /coherence over time/;
γ is /the app gets faster + more deterministic for your specific
workflows over time/. Everything else descends from those three.

*Expanded.* This page is the *navigation surface* — high-density
tour of the canonical layers in order, with deep-dive cross-refs to
the pages that own each concept. Not a re-explainer; not the
canonical reference for any one layer. Read this when you need
end-to-end comprehension fast (human onboarding, agent orientation,
cross-section reasoning); follow the cross-refs when you need depth.

* The mission (β)

*Summary.* The β statement, locked 2026-05-04: org-llm exists to
make a dream-state vault — one that thinks /with/ you — achievable
via agents, packaged as an opinionated dbt-shaped distro.

| Lead value | What the user GETS that they can't get elsewhere |
|------------+--------------------------------------------------|
| α          | Coherence over time across thousands of nodes    |
| β          | Dream-state vault — agents make the vault think  |
| γ          | App gets faster + more deterministic per /your/ workflows |
| substrate  | Org-is-Code — same toolchain as code applies     |

*Three first-usable criteria* (all required for v1.0):

1. Agents reliably high-quality — not flaky, not hallucinatory
2. Agent team coherent — defined roles, not 19 overlapping personas
3. Substantial user value demonstrably delivered (n=1 today, n=many later)

*Summary.* Three load-bearing principles + two operational
paradoxes. Each principle is a one-line claim; expansion lives in
the page it's canonized in.

| Principle                                          | Where canonized |
|----------------------------------------------------+-----------------|
| /Org is Code/ — files literally are code, not "documents" | [[id:30d4ee70-0472-4bcb-a02e-efde52bef3c6][architecture.org]] § Design rule — Org is Code |

*Operational paradoxes* (held in tension, both true):

- *Opinionated EXPERIENCE × agnostic SUBSTRATE* — Doom + opencode +
  dbt is the curated UX; runs on any OS, any git host, any cloud
  provider. /dbt-shape/.
- *Curated CORE × first-class EXTENSION path* — the Bridge Crew
  (≤7) ships in core; everything else is community-developable per
  [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-009]]/[[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-014 — Bridge Crew]].

* The architecture (data + sync + supervision)

*Summary.* Three layers, three deep-read pages.

** Data — files canonical, DB universal interface

| Layer                | Owns                                            |
|----------------------+-------------------------------------------------|
| Vault (=~/org/*.org=) | Canonical, durable storage; user edits in Emacs |
| dbt pipeline         | Forward direction: files → parsed tables → derived models |
| SQLite + sqlite-vec  | Universal SQL query/write interface; regenerable cache |
| Render hook          | Backward direction: DB writes → deterministic file rewrite |

Per [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-011]]: at the bytes level /everything is files/; the real
choice is which interface you put on the bytes. Per [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-013]]: that
interface splits cleanly into two tiers (next section).

** Sync — git is the entire mechanism

| Mechanism | Notes                                               |
|-----------+-----------------------------------------------------|
| =git push/pull= | Full multi-device sync; no custom protocol    |
| Per-device DB | Each device regenerates from synced files       |
| Per-device config | =Config(key, device, value)= per [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-012]]      |
| Conflict ladder | =merge=union= → org-format → org-aware merge driver |

Catastrophic loss is a re-clone event, not a data-loss event.
Mobile capture latency stays at local-disk speed.

** Supervision — deterministic trinity (Phase 2026-05.02 — supervision trinity)

| Registry              | Status            | Wiring                  |
|-----------------------+-------------------+-------------------------|
| Pre-flight resolvers  | 24.1 *shipped*    | =intercept_agent_prefix= ([[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-008]]) |
| Tool-failure recovery | 24.2 *shipped 2026-05-06* | =@recover= decorator wired at MCP tool sites |
| Confusion detector    | 24.3 *shipped 2026-05-06* (wiring v0.1 in progress) | Signal registry over =crew_log= |
| Manager quorum        | 24.4 open question | Async-only; never on critical path |

Each layer is a /registry/ — adding entries is one file/decorator,
not core surgery. Per the architecture design rule: pattern-matchable
confusions belong to code; reasoning-required confusions are reserved
for LLMs and prefer async/off-critical-path.

* The agents (Bridge Crew + extension)

*Summary.* The curated core agent team — locked at ≤7 in [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-014]]
(renamed from "Magnificent Seven" 2026-05-06 with Trek-canonical
handles):

| Agent       | Role                                          |
|-------------+-----------------------------------------------|
| =@picard=   | Manager — decompose / delegate / synthesise   |
| =@spock=    | Researcher — workhorse over the vault         |
| =@data=     | Scribe — capture-flow + drafting              |
| =@boothby=  | Hygiene — orphans, drift, broken links (Trek: Starfleet Academy gardener) |
| =@geordi=   | Analytics — owns dashboards + Superset surface (Trek: TNG chief engineer) |
| =@atoz=     | Wiki concept-graph specialist (Trek: TOS Mr. Atoz) |
| =@riker=    | General-purpose project tracker (Trek: TNG first officer / XO; scope expanded 2026-05-05 — DIY/lab/book/sprints, not just dev) |

Two patterns to know:

- *Agent-as-manager* — the agent /manages/ a substrate (resolver
  registry, recipe registry, doctor checks, config schema) without
  /becoming/ the substrate. Substrate stays deterministic code.
- *Spawned subagents ≠ @-agents* — different concept layer. Spawned
  subagents are ephemeral one-shot workers from the host (opencode,
  or any other MCP client like Claude Code); @-agents are durable
  personas with registry entries.
  They compose; they're not subsets.

*Extension path is first-class* (not afterthought) — Phase 2026-05.14.02 — DB-backed registry
user-supplied agents + Phase 2026-05.16 — literate MCP tools literate MCP tools (*shipped
2026-05-06*; wiring v0.1 in progress). Anything beyond the Bridge
Crew is community-developable per [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-009]]/[[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-014 — Bridge Crew]].

* The tools (data tier + effect tier)

*Summary.* Per [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-013]] — two named tiers, default strongly toward
the first.

** Data tools (dbt-tools, ~90% of surface)

| dbt mechanism | Used for                                   |
|---------------+--------------------------------------------|
| models        | read-side queries (views or tables)        |
| operations    | write-side; INSERT/UPDATE + render hook    |
| snapshots     | append-only history capture (retrospection) |
| tests         | declarative contracts agents trust         |
| macros        | parameterised SQL chunks                   |

Examples: =search_notes=, =ask_notes=, =count_across_vault=,
=recent_activity=, =agenda_view=, =mood_arc=, =tag_taxonomy=,
=capture_note= (operation + render hook), vault facts, hygiene scans.

| Surface     | Examples                                    |

| shell       | subprocess, file ops                        |
| granted-fs  | =read_file=, =list_directory= (allowlist)   |
| network     | http fetches, webhooks                      |

* The quality story (Three Laws + trinity + tests)

*Summary.* Quality is enforced at four levels — write-time, run-time,
build-time, and meta-time.

** Three Laws of Data Integrity (Asimov + plain)

| Law | Plain version |
|-----+---------------|
| 0th | An agent may not propagate vault state inconsistent with user intent — Phase 2026-05.02 — supervision trinity trinity enforces |
| 1st | Agent defers to user (open dirty buffer = queue the change)   |
| 2nd | Agent must propagate to canonical files unless 1st blocks      |
| 3rd | Agent preserves its own past via git audit; retry on regression |

Default mode is =auto-revert-mode= for clean buffers; user always
wins on collision; git remembers; engine retries.

** Supervision trinity (Phase 2026-05.02 — supervision trinity)

Three registries — pre-flight resolvers, tool-failure recovery hooks,
confusion detector. Each accepts new entries the way the recipe
registry accepts recipes. 24.1 / 24.2 / 24.3 all shipped (24.3
wiring v0.1 in progress); supervision trinity is feature-complete
modulo wire-up polish.

** dbt tests as agent contracts

Declarative tests in =schema.yml= run on every build. Agents trust
=SELECT * FROM recent_activity= because tests pass. =@boothby='s job
sharpens from "vague hygiene" to "read failing tests, propose fixes."

** Phase 2026-05.21 — multi-judge validation multi-judge (the meta-quality gate)

Validation framework's =judge_models= becomes a list; FOSS judges
(Llama 3.3, Qwen 2.5, DeepSeek R1) vote; reduces single-judge bias.
Sprint-eligible (~1d).

* The versioning shape

*Summary.* "First usable" is a sequential ladder, not exclusive
checkpoints.

| Level | What it means                                          |
|-------+--------------------------------------------------------|
| (a)   | Personally usable by the maintainer (today, daily-driver) |
| (b)   | Personally great — quality bar high enough to fully rely on |
| (c)   | Stranger-installable — someone else can adopt unaided   |
| (d)   | Multi-user community of practice                        |
| (e)   | Self-sustaining ecosystem with external contributors    |

*Where we are 2026-05-06:* late (a), reaching (b). v1.0 ≈ (c).
