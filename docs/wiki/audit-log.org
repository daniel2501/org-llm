* What this is

A living log of bidirectional audits between the wiki and the
codebase: where do wiki claims diverge from reality, and what
code surfaces does the wiki not yet describe?

Every audit pass appends a dated section. Each finding is
either =fix-applied= (the wiki was corrected in the same commit)
or =deferred= (parked here pending later work). The =deferred=
list is the agenda for future sweeps.

* How to run an audit

#+begin_src sh
# Manual: each wiki page's "Source files" + claims vs the
# referenced code. Cheap checks first:
ls $(grep -oE 'org_llm/[a-z_]+\.py' docs/wiki/*.org | cut -d: -f2 | sort -u)

# Codebase → wiki: spot-check helpers and verbs the code names
# that no wiki page describes:
grep -nE "^def [a-z_]+\(" org_llm/cli.py | head
grep -nE "^@app\.command|@.*_app\.command" org_llm/cli.py
grep -nE "^    @server\.tool\(\)" org_llm/mcp_server.py
#+end_src

The audit is a manual pass for now; a future pass might
automate some checks (file paths exist, commit anchors valid,
phase numbers match git log).

*** Walk
:PROPERTIES:
:STATUS: fix-applied
:END:

The wiki described a graph-traversal model (depth, edges, tag
co-occurrence). The actual =walk= verb is *not* graph traversal
— it's an LLM-driven attention picker that surfaces N notes
worth attention and extracts atomic factual claims for the
context overlay.

| Claim                                  | Reality                                                |
|----------------------------------------+--------------------------------------------------------|
| Traverses by id-link / tag co-occurrence / temporal proximity / backlinks | LLM picks N attention-worthy notes; user explains; LLM extracts atomic facts |
| Flags: =--id / --depth / --tags-min / --since-days / --no-llm= | =--window-days / -w / --max-nodes / -n / --pick / -p / --review / --no-save= |
| Output is "narrative through context graph" | Output is "lessons extracted to =llm-context.org=" |
| MCP tool: =walk_node=                  | Doesn't exist                                          |
| MCP tool: =add_disambig=               | Doesn't exist; =walk_save_disambiguation= is the real one |
| Tracks: notes (only one wired)         | =notes= wired; =dailies= + =projects= are Phase 2026-07.07 — dailies as walk targets-3 stubs |

The walk page's CONCEPTUAL framing was fundamentally wrong — it
treated walk as a retrieval mode (alongside ask), but walk is a
KNOWLEDGE-CAPTURE mode (alongside =context add=). Rewritten.

** Reality → wiki: code surfaces with no wiki coverage

These are real features the audit surfaced that no wiki page
yet describes. Most are candidates for new wiki pages; some are
sub-features of existing pages.

*** Trust-on-first-use for skills
:PROPERTIES:
:STATUS: fix-applied
:END:

The first time a skill source SHA changes, =skill <name>=
prompts the user to inspect the source before running. The
SHA gets stored in =Config.trusted_skills=; re-runs are quiet
until the source changes. This is a real safety property and
deserves explicit wiki coverage. Added to skills.org.

*** =doctor= subcommand structure
:PROPERTIES:
:STATUS: fix-applied
:END:

The =doctor= verb has both flag-driven (legacy) and
subcommand-driven (new) entry points: =doctor walkthrough=,
=doctor fix=, =doctor power-boost=, =doctor install=,
=doctor diagnose-cards=. Doctor wiki page now mentions both
forms.
