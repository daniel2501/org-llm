* Summary

*Summary.* First real *spike-team* exercise of the Agor integration
(per [[id:1e75cdba-f743-456d-9d0f-07b9e0da33ac][multi-agent-org-llm]] § Spike teams) on a doc-shaped target — the
license-decision investigation pending under [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-010]] / [[id:190baa35-06d1-4b34-a67d-2926859f47cb][DEC-017]]. Captain
=@picard= dispatched 3 children (=@spock= researcher × 2 attempts +
=@data= drafter) on a shared worktree-as-board. Total cloud spend
$0.187, wall ~7 min. *Verdict: AGPLv3-primary holds*; EUPL v1.2
demoted from co-fallback to "watch v1.3"; the 2025-05-05 draft's
Redis SSPL→AGPLv3 framing was *factually wrong* and the team caught
it. /Updated artifact:/ =/tmp/license-decision-2026-05-06.md=.

*Expanded.* This is a *minimum-viable* spike-team run (per the
mission's "≥1 captain spawn + ≥1 child round-trip via MCP" floor),
which expanded to the full 3-role shape inside budget. It validates
the team-shape end-to-end: parent session genealogy carries 3
children correctly; sibling discovery via shared =worktree_id= is
exactly what the [[id:1e75cdba-f743-456d-9d0f-07b9e0da33ac][multi-agent-org-llm]] § "Sibling-session by
boardId" pattern named; one bug surfaced (default child
=permission_config.mode= is =acceptEdits=, blocking WebSearch with
no visible permission-grant REST endpoint). The captain's *one*
turn dispatched 2 children + reported their session IDs in 48s for
$0.12 — the part Agor genuinely earned. The synthesis itself was
done by the harness (parent agent), not by another captain turn,
to stay inside the spend cap.

* Final license recommendation

*One-liner:* **AGPLv3 primary; add DCO (not CLA) for contributor
compliance; reject SSPL/Hippocratic/ACSL as non-OSI; demote EUPL
v1.2 from co-fallback to "watch v1.3 release."**

Full artifact at =/tmp/license-decision-2026-05-06.md=. Key
corrections from the 2025-05-05 draft:

- *Redis framing fixed.* The earlier draft said "Redis SSPL→AGPLv3
  reversal in 2025" — this is unverified by training data. =@spock=
  caught it: Redis went *BSD → SSPL + RSALv2* in March 2024, which
  triggered the Linux Foundation Valkey fork. No AGPL reversal in
  training data through August 2025.
- *Elastic confirmed.* August 2024 trilicense (AGPLv3 + SSPL +
  Elastic License 2.0). This part of the 2025-05-05 draft was
  correct.
- *Sentry posture clarified.* Sentry uses FSL-1.1 (2-year sunset
  to Apache 2.0), not AGPL — they're the "eventually FOSS" camp,
  not copyleft.
- *EUPL v1.3 not released.* As of training cutoff, EUPL 1.2 (2017)
  remains current; v1.3 is unconfirmed. Demote EUPL from
  co-fallback to "watch."
- *DCO over CLA.* New addition: pair AGPLv3 with a Developer
  Certificate of Origin (Nextcloud/Signal pattern), not a full CLA
  — keeps the process FOSS-idiomatic while putting employer-IP
  compliance burden on contributors' employers.

* Counterfactual: how solo =delegate()= would have looked

Comparison is honest, not boosterish — both shapes have wins.

| Dimension          | Spike team (this run)                                               | Solo =delegate()= via @-prefix proxy                              |
|--------------------+----------------------------------------------------------------------+--------------------------------------------------------------------|
| Cloud cost         | $0.187                                                              | ~$0.10 — single Sonnet call, no spawn cascade overhead             |
| Wall clock         | ~7 min (incl. permission-bug diagnosis)                             | ~2 min — one round-trip, no polling                                |
| Depth of research  | =@spock= caught Redis-framing error AND verified Elastic/Sentry/Google AGPL allowlist independently | One Sonnet call would have re-stated the original 2025-05-05 framing without the cross-check |
| Audit trail        | 3 sessions retained on disk + this org doc + recommendation artifact + captain's log entry  | One =manager-log.jsonl= entry + the artifact                       |
| Worktree pinning   | Each child in =spike-license-637257= worktree — clean isolation     | No worktree; runs in caller's CWD                                  |
| Robustness to bugs | First =@spock= attempt got stuck (permission inheritance bug); workaround visible | Single point of failure, but fewer moving parts to break             |

*Honest read.* Solo would have produced a recommendation faster
and ~half the cost. But solo *would not have caught* the
Redis-framing factual error in the existing draft, because solo
=delegate()= reuses the caller's context — the wrong framing would
have been carried forward. The team-shape's two-turn structure
(captain dispatches; researcher cross-checks; harness synthesizes)
is what produced the *correction*, not just a confirmation.

* Verdict

*Did the spike-team shape earn its keep on this job?* /Marginally yes —
on this specific run./

The team-shape produced a factually corrected recommendation that
solo would have rubber-stamped. That's the real win — the kind of
"big" work [[id:1e75cdba-f743-456d-9d0f-07b9e0da33ac][multi-agent-org-llm]] names. The cost premium ($0.087 over
estimated solo) is acceptable for license-decision-grade work.

*But it's a 60/40 call, not a 90/10 one.* Three caveats:

1. *Most of the wall-clock cost* came from diagnosing the
   permission-inheritance bug (= ~3 of ~7 min). On a clean run
   that goes away; the team would beat solo on time, not lose to it.
2. *Synthesis happened in harness*, not in another captain turn.
   That's where Opus would have lived. Skipping it kept us under
   budget but means this run only validated dispatch + sibling
   genealogy, not the full captain-loop. A cleaner pilot would
   include a 2nd captain turn that reads child outputs and emits
   the final doc — lifting cost to ~$0.30 but exercising the full
   shape.
3. *The work was doc-shaped, low-stakes, reversible.* Spike-team
   shines harder on cross-cutting code work where the children are
   doing different *kinds* of work in different worktrees (Phase
   26.2 — physical extraction is the Schelling-point next pilot).

#+begin_quote
=BUG-04= — child sessions inherit =permission_config.mode = "acceptEdits"=
even when the parent was launched via =claude -p --permission-mode
bypassPermissions=. The CLI flag scopes only the parent process; the
DB record carries =acceptEdits=, and child spawns inherit from there
(=daemon/mcp/tools/sessions.js:14293=). =WebSearch= and other non-edit
tools then block forever with no visible permission-grant REST
endpoint. /Workaround:/ =PATCH /sessions/{parent}
{"permission_config":{"mode":"bypassPermissions"}}= before the spawn,
or formulate child prompts to skip web tools.
#+end_quote
