* Summary

*Summary.* As of May 2026, FOSS still trails Claude on *general*
intelligence (Arena ~220-point gap, AA Intelligence Index ~24-point
gap), but matches or beats Claude on *coding-specialized*
benchmarks via Kimi K2.6 (1T-param MoE, open MIT-modified weights,
SWE-Bench Pro 58.6% — tied with GPT-5.5). Cost: top FOSS is 5-36×
cheaper than Claude; Kimi K2.6 specifically is ~8-10× cheaper than
Opus 4.7. The realistic path to "competitive with Claude on cloud
compute" today is *Kimi K2.6 via Moonshot direct API* for
coding-shaped work; for non-coding it remains a quality compromise
that pays in cost/speed.

*Expanded.* This page captures the May 2026 snapshot of the FOSS
landscape relevant to org-llm's "Agor crew uses no Claude" rule
(see =feedback_agor_no_claude= memory + [[id:1e75cdba-f743-456d-9d0f-07b9e0da33ac][multi-agent-org-llm.org]]
§ Crew runtime). The rule is achievable today *for coding-shaped
team work* via Kimi K2.6; for general open-ended judgment, the
quality gap remains real and is closed via *D3 — per-role training/
RAG* rather than raw model power. The four-dial framing below maps
each lever to current evidence + practical paths.

* The four dials

| Dial | What it controls | Org-llm status |
|------+------------------+-----------------|
| *D1 — Model power/size* | Raw parameter count + architecture quality | Validated qwen30 (rounds 5-10), tested 70b/r1/120b (round-11 cut short); Kimi K2.6 + DeepSeek-V4 + gpt-oss-120b sweep planned (round-12) |
| *D2 — Cloud hardware/provider* | Inference latency, throughput, cost | Currently OpenRouter only; direct Moonshot/DeepSeek APIs are 5-20× cheaper for same models; Modal/RunPod self-host viable past ~5K daily calls |
| *D3 — Per-role training/RAG* | Persona-targeted knowledge (org-mode, our wiki, code corpus) | Untested; *highest leverage* for closing org-llm-task-specific gap |
| *D4 — Operating model + harness design* | How agents coordinate, monitor, intervene | Two-phase + harness-as-mailman validated (rounds 8-10); D+B (contingencies + bounded re-prompts) per [[file:picard-agor-primer.org][picard-agor-primer.org]] is next step |

The dials are *interrelated*: D2 only matters once D1 is fixed; D3
multiplies whichever D1 you pick; D4 is largely orthogonal but
amplifies D1+D3 results.

** Crossover point: API vs self-hosted

For typical org-llm task (~50K tokens):
- API: ~$0.04/task (Kimi K2.6 via Moonshot)
- Self-hosted on H100: $3.95/hr / 200K tokens/hr serving = $0.02/task break-even

*Crossover ≈ 5,000-10,000 tasks/day.* Below that, API wins on cost.
Above, self-host wins. Org-llm is currently far below — *use direct
APIs*. Revisit when scaling to thousands of daily agent calls.

* Path to "competitive with Claude on cloud compute"

The honest answer depends on which axis you optimize:

| If you optimize for… | Winner today | How to get there |
|----------------------+--------------+------------------|
| Lowest cost | gpt-oss-120B / DeepSeek-V4-Flash | Just swap model id in harness |
| Fastest latency | gpt-oss-120B (235 t/s) | Pick provider with batched serving (Fireworks turbo, Together turbo) |
| Best coding quality | *Kimi K2.6* | Moonshot direct API; swap into specialist modelConfig |
| Best general intelligence | Claude Opus 4.7 (proprietary) | Cannot match with FOSS today |
| Best on a *specific* org-llm task | *FOSS + RAG + per-role fine-tune* (D3) | Highest leverage; biggest setup |

** For org-llm specifically (May 2026 recommendation)

1. *Adopt Kimi K2.6 as the default specialist model* for coding/wiki
   tasks. Replaces qwen3-coder-30b in the production crew runtime.
2. *Keep DeepSeek-V4-Pro on the menu* for reasoning-heavy tasks
   while the 75% discount runs (until 2026-05-31).
3. *Defer self-hosting* until daily agent-call volume crosses ~5K.
4. *Invest in D3* — RAG over =docs/wiki/= + per-persona retrieval
   over corpus + fine-tuning on org-llm-shaped tasks. This is the
   one dial that *closes the gap on org-llm-specific work* rather
   than chasing general intelligence.
5. *Operating-model improvements (D4)* — D+B pattern (plan with
   contingency branches + bounded re-prompts) per
   [[file:picard-agor-primer.org][picard-agor-primer.org]] amplifies
   whichever D1 we pick.
