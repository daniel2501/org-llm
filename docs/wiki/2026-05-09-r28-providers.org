* §8 — Modal-Kimi container troubleshoot (R28 dead-end)

*Summary.* Modal =org-llm-kimi-k26= deployed but containers crash
on =KeyError 'VLLM_API_KEY'=: Modal secret name is =vllm-bearer-key=
(env var =VLLM_BEARER_KEY=) while =serve_kimi.py= reads
=os.environ['VLLM_API_KEY']=. =serve_kimi.py= source is *missing
from repo + git history*. K2 OR-route (§5) is workaround, not fix.

| Surface              | State                                                          |
|----------------------+----------------------------------------------------------------|
| Modal app            | =org-llm-kimi-k26= deployed                                    |
| Container crash      | =KeyError 'VLLM_API_KEY'= on cold-start                        |
| Modal secret name    | =vllm-bearer-key= → env =VLLM_BEARER_KEY=                      |
| Code reads           | =VLLM_API_KEY=                                                 |
| =serve_kimi.py= file | /MISSING/ — no =scripts/=, no =modal/=, no git log hit         |
| Related files only   | =_modal_kimi_health_check.py=, =_w2_direct_kimi_probe.py= (no deploy) |
| R29 path A           | reconstruct + fix env-var read                                 |
| R29 path B (rec.)    | port to RunPod-vLLM (mirror K20 template; same proxy pattern)  |

*Recommendation.* Path B — inherits K20's working pod template, no
Modal dependency, kills missing-source mystery. Trade-off: Modal
queue-based billing (cold-start free) vs RunPod $/hr always-on. For
K2 sentinel use, RunPod-vLLM pause/resume matches K20 exactly.
