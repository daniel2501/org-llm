#+TITLE: Skills — org-babel-driven LLM workflows
#+FILETAGS: :wiki:concept:skills:org-babel:
#+OPTIONS: toc:nil num:nil

* What a skill is

A reusable LLM workflow defined as an =org-babel= source block
tagged =:skill:=. The block lives in a normal org file in your
vault; =org-llm= indexes it, registers it as an MCP tool, and
exposes it as a slash command in opencode.

The pattern: literate config / code as the source of truth, the
SQLite registry as the cache. Edit the org block, re-tangle, the
skill updates everywhere.

* Anatomy of a skill

A minimal skill:

#+begin_src org
,* Weekly review summary :skill:
,:PROPERTIES:
,:SKILL_NAME: weekly-review-summary
,:SKILL_LANG: python
,:SKILL_MODEL: chat_model
,:END:

,#+begin_src python
import sys
prompt = f"""
Summarize this week's notes in 5 bullets, grouped by theme:

{sys.stdin.read()}
"""
print(prompt)
,#+end_src
#+end_src

The =:skill:= tag on the heading marks the block; the
=:PROPERTIES:= drawer configures it:

- =SKILL_NAME= — addressable name (defaults to the heading,
  lowercased + spaces → underscores)
- =SKILL_LANG= — interpreter (=python= / =sh= / =bash= /
  =shell=); default =python=
- =SKILL_MODEL= — config key naming the model to route to
  (=chat_model= / =fast_model= / =reason_model= / =text_model=
  / =code_model= / =cloud_model=); default =text_model=

The first =#+begin_src= block under the heading IS the source.
Trust-on-first-use (below) hashes that source before the first
run.

* Three roles

| Role            | What it does                                          |
|-----------------+-------------------------------------------------------|
| Skill builder   | Writes the org block — that's all                     |
| =skill-index=   | Scans the vault, registers each =:skill:= block       |
| =run_skill=     | MCP tool that pipes input through the skill, runs it  |

=org-llm skill-index= is idempotent — re-run after editing.

* Why org-babel?

- *Literate*: prompt + code + docs in one place; the org file is
  the manual.
- *Tangled*: the skill body extracts to a real script
  (=:tangle <path>=), so it's executable outside the LLM
  context too.
- *Versioned*: lives in your vault git, evolves with you.
- *Discoverable*: the same vault that holds your knowledge
  holds your workflows.

* Skill registry

The =Skill= table caches what =skill-index= scans
(=org_llm/skills.py:Skill=):

#+begin_src python
class Skill(Base):
    __tablename__ = "skills"
    id         = Column(Integer, primary_key=True)
    name       = Column(Text, nullable=False, unique=True)
    lang       = Column(Text, nullable=False, default="python")
    model_key  = Column(Text, nullable=False, default="text_model")
    source     = Column(Text, nullable=False)    # raw src block body
    file_path  = Column(Text, nullable=False)
    heading    = Column(Text, nullable=False, default="")
#+end_src

=list_skills= MCP tool reads this; the workspace prompt
includes the names ("Skills: weekly-review-summary,
extract-todos, generate-test-plan").

* Trust-on-first-use safety

Skills execute arbitrary code as the current user. The first
time a skill source runs, =org-llm skill <name>= prompts the
user to inspect the source, then records a SHA-256 of the
source body in =Config.trusted_skills=:

#+begin_example
trusted_skills = "weekly-review-summary:abc123def4,extract-todos:fa01122334,…"
#+end_example

Re-runs are silent until the source changes — any edit
invalidates the trust entry and re-prompts. =--yes= bypasses
the prompt for scripted use.

This catches the "shared org file ships a hostile skill" attack
class. Skills landing from someone else's vault force a manual
review.

* Conversational use

Inside opencode:

#+begin_src
User: run my weekly-review-summary on this week's notes
Model: → run_skill(name="weekly-review-summary",
                    input=<this week's nodes>)
Model: <returns the 5-bullet summary>
#+end_src

The model picks =run_skill= when the user's verb maps to a
registered skill name.

* How to configure

** Env vars
- =ORG_LLM_DB= / =ORG_LLM_ORG_DIR= — same as everywhere; the
  skill index honors the override.

** CLI flags
#+begin_src sh
org-llm skills                              # list registered skills (table)
org-llm skill-index                         # scan vault, upsert all :skill: blocks
org-llm skill <name> "<input text>"         # run with positional input
org-llm skill <name> --node "<node title>"  # use that node's body as input
org-llm skill <name> --yes                  # skip the trust-on-first-use prompt
org-llm skill-new                           # scaffold a new skill block (interactive)
org-llm skill-examples                      # show example skill blocks
#+end_src

** Skill-block properties (set in =:PROPERTIES:= drawer)
- =:SKILL_NAME:= — explicit name (otherwise derived from the
  heading, lowercased + spaces → underscores)
- =:SKILL_LANG:= — =python= / =sh= / =bash= / =shell=; default
  =python=
- =:SKILL_MODEL:= — config-key name (=text_model= / =chat_model=
  / =reason_model= / =fast_model= / =code_model= / =cloud_model=);
  defaults to =text_model=

There is no =SKILL_INPUT= or =SKILL_TIMEOUT= property. The
input is whatever the caller passes; timeouts are governed at
the =llm.chat()= layer.

** Conversational (opencode / pi / MCP clients)
- =/skills= slash command — list registered skills
- =/skill <name>= — invoke
- Natural language: "run my weekly review skill on the last 7
  days" — model picks =run_skill=
