* What this is

A classified inventory of every domain in =org-llm= with an
assessment of which are agents today, which should be recast as
agents, and which stay as framework / infrastructure. Sorted from
*least interesting at top → most interesting at bottom*: the punch
line is that scrolling down reveals what we'd actually want to
build at 2am.

Use this as the source-of-truth catalogue when planning new
work. The [[file:agent-framework.org][agent-framework architecture
doc]] describes HOW agents compose; this page describes WHICH
agents exist (and which we want next).

* Reading the table

The bottom 6 rows are where the rave-coding voltage is highest:

- *=@coach= / =@medic=* — read what you already write and reason
  about *you*. Compounding personal-data agents. (=@journalist=
  shipped 2026-05-03; first of the trio live.)
- *=@inbox= / =@horologe= / =@bookkeeper=* — ingest *new* axes
  (email, calendar, money) into the same vault grammar. Each
  opens a domain that wasn't there before.
- *=@oracle=* — different I/O modality. Voice in, voice out. The
  vault listens.
- *=@agentsmith=* — meta-agent. Interviews you about a new
  agent's purpose, drafts the persona, picks the tool roster
  from existing MCP entries, suggests triggers + icons + a
  hygiene scan, validates against a test prompt before it lands.
  Self-bootstrapping; turns "I want an agent for X" into a
  shipped agent in one conversation.

  ships with the data.

Each is one entry in =org-llm-agents.org= + one persona block +
optional triggers. ~30-60 minutes per agent.

* Icon palette (nerd-font / utf-8 / ascii fallback ladder)

Each agent ships with a small set of icons keyed off its domain.
Three-step fallback: nerd-font glyph (preferred when the user's
terminal has nerd fonts installed) → utf-8 emoji (works in
modern terminals) → ascii (always works).

The host's sidebar renderer picks the first viable tier based on
=icon_pack=auto|nerd|utf8|ascii= and the detected font. Agents
declare their icon set via =Agent.icons= in the new shape; today
this stays as a documented mapping, lifted into code in Phase
23.1.

The renderer's selection ladder:
1. If =icon_pack=ascii=, always use the ascii column.
2. If =icon_pack=utf8= OR a nerd-font glyph fails to render
   (probe via fc-list for the patched font), use the utf-8
   column.
3. Otherwise (default =auto= with nerd font detected), use the
   nerd-font column.

Sidebar status cards already show category-flavoured icons (the
HEALTH section's =cpu/memory/thermal= rows). Agents extend this
pattern; the format_prefetch_block can prefix lines with the
agent's nerd-font glyph so the chat surface visually distinguishes
"weather is talking" from "scribe is talking".

* Architectural note

Every "promote to agent" row gets the same shape — see
[[file:agent-framework.org][agent-framework.org]] for the
formal structure:

- a persona system prompt (the *voice* — that's the LLM-leverage
  part)
- a tool roster pulling from existing MCP entries
- triggers for auto-routing
- optional recipes for orchestration pre-fetch
- optional hygiene scan (the agent's domain-specific "what
  should I do about my vault")
- optional inferrers for cached domain facts
- declared capabilities (=read.vault=, =write.vault=, =shell=,
  =external.network=, etc.)

Adding a new agent is one entry in =org-llm-agents.org= + a
Python persona class (or just an entry in
=_PRECONFIGURED_AGENT_PROMPTS=). The framework absorbs them all.
