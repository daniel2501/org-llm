* Bugs found + fixed during verification

** Bug 1 — P1-7 commit reverted P2-4 wall_seconds

*Summary.* Commit =9fc4c2c= ("feat(bench): P1-7 wire S1-S4 composition
strategies") was branched off the pre-P2-4 base. When merged it did
=-_r26_t0 = time.time()= and removed both =cell["wall_seconds"]= writes
in =run_one_cell=, silently undoing =c77fd51= ("fix(bench): P2-4
per-cell wall_seconds for ALL variants").

*Expanded.* P1-7's diff shows the regression on lines 1388-1395 +
1418-1419 + 1487-1488. After =git restore=, =run_one_cell= contained
no =_r26_t0= at all; only =execute_cell='s wrapper at L1962 had
=wall_seconds= — which is the very bug P2-4 was meant to fix (see
P2-4 commit message). Without P2-4, only K5-claude-solo cells get
=wall_seconds= in =cell_result.json=; all FOSS cells lose per-cell
walltime instrumentation.

*Fix.* Re-applied the three P2-4 edits inline as part of this
verification (added a comment trailer noting the P1-21c re-apply).
Now =run_one_cell= captures =_r26_t0= at entry and stamps
=wall_seconds= before both =write_cell_result= sites. Verified via
=inspect.getsource=: 2 occurrences of =cell["wall_seconds"] = round(time.time() - _r26_t0, 1)= present.

*Recommendation.* When P1-7 is rebased / future composition-strategy
edits land, ensure they're branched off the latest =_round26_dials.py=
HEAD, not pre-P2-4. The narrow fix here re-applied P2-4 directly.

** Bug 2 — _r26_design_patch.py overwrote post-fork patches

*Summary.* =_r26_design_patch.py='s =fork_harness()= unconditionally
copies =_round25_dials.py= to =_round26_dials.py= with a sed-rename. It
docstrings as "Idempotent" but never checks DST-exists. Since
=_r26_launch.sh= step 1 calls this script every launch, every
post-fork patch (P1-7 S1-S4 wiring, P1-11/12/13 file contracts, P2-4,
P1-15 BK3 hook) would be obliterated on each run. Confirmed during
this audit: a single =python3 scripts/_r26_design_patch.py= reverted
the harness to a 2075-line R25-equivalent; all patches gone.

*Fix.* Added a DST-exists guard. If =_round26_dials.py= already exists
AND has been round-id-renamed (markers =_round26_dials_artifacts= +
=R26_LIVE= present, no =_round25_dials_artifacts= remnants) AND is at
least as large as a freshly-renamed SRC, skip the overwrite. To force
re-fork (e.g. on intentional R25 update), set =R26_FORCE_REFORK=1=.
Verified: re-running =_r26_design_patch.py= now preserves all post-fork
patches; all 5 P0 probes still PASS.

*Recommendation.* Document the =R26_FORCE_REFORK= env in
=_r26_launch.sh='s Env overrides comment block when the launcher next
gets a touch-up. Also consider applying P1-7 + P1-11/12/13 + P2-4 to
=_round25_dials.py= upstream so a forced re-fork doesn't regress
behavior.
