* Summary

*Summary.* Four parallel agents analyzed R17 from quality, Pareto,
walltime, and provider/cache angles. Convergent finding: K8-deepseek-V3
is the under-recognized Pareto winner across all four lenses — quality
18.6/25 (3rd), cost $0.0005/u (cheapest by 2×), zero destructive
behavior, 87.5% multi-cell cache hit rate (only working cache loop).
R17's mechanical leader K11-qwen3coder is legitimate (no destruction)
but cost-inefficient (34× cost for 14% quality lift over K1). R17's
biggest wall-time problem was a single-cell long pole (K15-kimi-thinking
756s on B1) — drop it from layer-1, wall halves. Provider pinning
mostly didn't take (only 2/12 warmups hit pinned broker; missing
=allow_fallbacks: false=).

*Expanded.* This is the consolidated read across all four agents +
my own analysis. R18 advancing set + must-fix gotchas + R18 design
adjustments fall out of the cross-cutting findings. *The decisive
strategic finding is from the cost-per-quality numbers: K8 + K1 are
~23-33× cheaper than Claude per quality unit, which means R18 has
enormous spend headroom to ramp depth + breadth + composition
without breaking the cost-effective-FOSS thesis.*

* The strategic shift — cost is no longer the constraint

R17 quality judge produced cost-per-quality numbers that change the
R18 design fundamentally:

| Variant | Cost-per-qpt | Multiplier vs cheapest |
|---------+--------------+------------------------|
| K8-deepseekV3 | $0.00021 | 1.0× (cheapest) |
| K1-qwen30     | $0.00031 | 1.5× |
| K11-qwen3coder | $0.025 | ~120× (premium tier) |
| K5-claude-solo | ~$0.007 | *33× more than K8; 23× more than K1* |

*Implication.* We can spend 23-33× MORE per FOSS cell and still be
cheaper per-quality than Claude. For R18:
- *Sample depth*: n=3 → *n=10-15* default (cost: 3-5× R17 = ~$15-25)
- *Top-K advancing*: top-3 → *top-5* (K1, K8, K11 + 2 contenders)
- *Modal-Kimi continuous-warm*: ~$8/night for tail-cut (was optional)
- *LoRA fine-tune*: unconditional launch ($13-22, was gated on data size)
- *Hedged retry on >90s cells*: must-have, not nice-to-have
- *All Tracks D-P in scope* for v1, not stretch

Realistic R18 spend with all upgrades: *~$110-200 — well under $375
cap*. Full doc at =docs/wiki/2026-05-08-foss-spend-headroom.org=.

* Cross-cutting themes (across all 4 agents)

** Theme 1 — K8-deepseek-V3 is the new default

All 4 agents converge:

| Agent | K8-V3 finding |
|-------+--------------|
| Quality | 18.6/25 quality (3rd, near K1's 19.0) |
| Pareto | $0.0005/u cheapest by 2×; *Pareto-optimal among FOSS* |
| Walltime | 26.4s median, 102s max — efficient |
| Provider/cache | 103,104 cached tokens across 7 cells; *only working multi-cell cache loop (87.5% hit rate)* |

R18 should make K8-V3 the *default workhorse* (was K1).

** Theme 2 — K11-qwen3coder is real but wasteful

| Agent | K11 finding |
|-------+-------------|
| Quality | 17.3/25 (4th); legitimate (no destructive) but inserted 6 instead of 5 on B1, fabricated GPL-3.0 author header on B25 |
| Pareto | 34.2× cost ratio buys +14% quality; spent $0.069 on cosmetic 2-line edits where K8 spent $0.005 doing real work |
| Walltime | bimodal: median 16s, max 171.6s (single B11 thrash) |
| Provider/cache | Served by Together; zero cached tokens (route doesn't expose) |

R18 verdict: keep K11 for *high-stakes tasks only* (B11 DEC, complex composition); A/B against K8 + K1 before defaulting widely.

** Theme 3 — R17's anomalies were INFRASTRUCTURE, not models

The "shocking" R17 mechanical movements were all infra failures, not
model regressions:

| Apparent | Actual cause |
|----------+--------------|
| K7-qwen72b 162→0 collapse | TCP-level =IncompleteRead= mid-stream from DeepInfra |
| K13-V4-pro all silent | 2 cells died at git worktree concurrency race; 1 from GMICloud drop |
| K16/K17/K18/K19 all silent | Provider routing failures + invalid model IDs |
| Provider pins didn't take | Missing =allow_fallbacks: false= — OpenRouter treats =order= as advisory |

These are FIXABLE. R18 must add:
- Worktree-add mutex
- Provider failover on TCP drops + correct broker remap
- =allow_fallbacks: false= on PROVIDER_PINS
- Per-variant explicit fallback chains

** Theme 4 — Wall-time is dominated by ONE long pole, not parallelism limits

Walltime agent's correction: real efficiency = 25.4% (achieved 2.03× of
ideal 8×). My duration doc claimed "~9× speedup" which was misleading
— I was comparing total wall to *sequential equivalent*, not *theoretical
8× ceiling*.

The real story: layer1 wall = 794s, of which 756s = K15-kimi-thinking
alone. With K15 dropped from layer1, run wall would have been ~8.7 min
instead of 18.5 min. *The single biggest R18 lever isn't more workers;
it's not co-scheduling thinking models with downstream-blocking layers.*

** Theme 5 — Adaptive abort under-tuned, not over-tuned

| Datum | Value |
|-------+-------|
| Adaptive abort fires | 5 cells |
| False positives | 0 (all aborted cells scored 0) |
| Cells that DODGED abort via K11/K7-thrash | 3 (notably K11/B11/layer2: 15 iters, 10 failed edits, 13 nudges, 1 success) |

Abort needs new triggers:
- =consec_failed_edit_iters >= 3= → cut (catches K11-thrash)
- =nudges >= 5= → cut (catches model not learning from feedback)
- =wall >= per_cell_cap= → cut (catches everything)

** Theme 6 — Cache savings real but smaller than predicted

R16 audit predicted 22-27% input cost savings if pins held. R17 actual:
*14.6% of input cost (~$0.12 of ~$3.23)*.

The miss is structural: K1 + K11 (26 cells, biggest spend) served on
Novita/Together which don't expose cache hits to OpenRouter at all.
Only K8 has a working multi-cell cache loop.

R18 fix: re-pin to brokers that actually serve+cache (DeepInfra for
K2/K6/K7/K8, Novita for K15, SiliconFlow for K17, Mistral for K9).

* R18 design adjustments (deltas from existing R18 design doc)

** Spend headroom unlocks bigger R18 (the cost-finding strategic shift)

| Was | New |
|-----+-----|
| n=3 default sampling | *n=10-15 default* on layer-2 sweep |
| Top-3 advancing | *Top-5 advancing* |

** Modal-Kimi (DEPLOYED) reframes K2 + K15 routes

Kimi cells (K2, K15) currently dominated by long-tail Parasail latency
(135s, 756s). Modal-Kimi serves at sub-second TTFT. R18 should:
- Route K2 + K15 to Modal-Kimi (=https://daniel2501--org-llm-kimi-k26-vllm-serve.modal.run=) as primary
- OpenRouter as fallback if Modal cold-starts

This alone saves ~10 min on R18 wall.

* Disagreements between agents (none material)

All 4 agents agree on:
- K8-V3 promotion
- K11 quality is real (not destructive) but cost-inefficient
- Worktree concurrency is the #1 infra bug
- Provider pinning needs fundamental rework
- Adaptive abort needs new triggers

The walltime agent's "25.4% efficiency" corrects my earlier "9× speedup"
claim. My doc compared total wall to sequential equivalent (which
*is* a 9× compression in calendar time) — not theoretical 8× parallelism
ceiling (which is 25.4% efficient). Both numbers are useful for
different framings.
