plan's §13 verify each P0 patch actually changes runtime behavior
(addressing PM6 — the verification gap that let 3 of 11 R25

** DONE P0-1: Fix top-3 selector dedupe by variant
   - shipped; acceptance probe passed (synthetic cells K1/K2/K8 → returns [K1, K2, K8] in order)
:PROPERTIES:
:ESTIMATE: 30 min
:SOURCE:   r25-quality-judge §R-2; case-studies §P0
:DEPS:     none
:END:

Current bug at =scripts/_round25_dials.py:1675=:
=top3_foss = [c["variant"] for c in foss_cells[:3]]= picks
individual /cells/ not distinct /variants/. R25 had all 3 top
cells as K1 → L2/L3/BK collapsed to K1-only.

Fix: aggregate by variant first, rank by per-cell mean (not sum,
so wall_cap kills don't dilute), take top-3 distinct variants.

*Acceptance probe.* Run synthetic =top3_foss=...= with mocked
cells where K1 has 50 cells of mean=23, K2 has 40 cells of
mean=15, K8 has 25 cells of mean=10. Assert returns exactly
=["K1-qwen30", "K2-kimi-k2.6", "K8-deepseekV3"]= in that order.

** DONE P0-2: Wire K2 max_tokens through SpecialistTask + _chat_completions
:PROPERTIES:
:ESTIMATE: 2 hr
:SOURCE:   r25-providers §1; case-studies §P0
:DEPS:     none
:END:

R25 P5 patch defined =_R25_VARIANT_MAX_TOKENS= dict but nothing
read it. Default 8000 still fired. K2 produced 22-28k char
prose, hit 16 WALL_CAP kills.

Fix: add =max_tokens: Optional[int]= to =SpecialistTask=
dataclass; thread through =_chat_completions= override (default
8000 → variant-specific cap when present); read
=_R25_VARIANT_MAX_TOKENS= in =run_specialist_for_cell= per
variant name.

*Acceptance probe.* Send a long-prompt to K2 via the harness;
assert response =output_chars ≤ 16k= (4096 tokens × ~4 chars/tok
= ~16k char ceiling). Run 3 sample probes; all must pass.

** DONE P0-3: WALL_CAP runtime kill (TPE without context-manager)
   - shipped; outer worker freed at cap (probe: 5s exit on 5s cap = PASS); inner thread leaks until natural exit (acceptable trade) (replace ThreadPoolExecutor shim)
:PROPERTIES:
:ESTIMATE: 1 hr
:SOURCE:   r25-walltime §2; case-studies §P0
:DEPS:     none
:END:

R25's =with ThreadPoolExecutor(max_workers=1) as _inner= shim
calls =shutdown(wait=True)= on context exit, blocking outer
worker until inner thread finishes. Cell records
=wall_cap_killed:400s= label but actual =wall_seconds=
ranged 455-1697s.

Fix: replace ThreadPoolExecutor shim with =threading.Event=
polled by =run_one_cell= at each tool-call boundary (or
=multiprocessing.Process= terminated cleanly).

*Acceptance probe.* Spawn a synthetic 500s cell (=time.sleep(500)=
in a tool); assert kill fires within 410s. Repeat 3 times; all
must pass.
