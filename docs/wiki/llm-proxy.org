#+TITLE: LLM proxy
#+FILETAGS: :wiki:proxy:opencode:phase17:
#+OPTIONS: toc:2 num:nil

* What this is

A small HTTP server, [[file:../../org_llm/llm_proxy.py][=org_llm/llm_proxy.py=]], that sits between
opencode and the upstream LLM endpoint (ollama, OpenRouter, etc.).
=org-llm launch= starts it on a free localhost port and rewrites
opencode's provider config so every chat-completion request flows
through it.

The proxy runs a chain of *interceptors* against each request:

#+begin_src text
    interceptor(request_body) -> ProxyResponse | None
#+end_src

If any interceptor returns a =ProxyResponse=, the proxy short-circuits
— that response goes back to opencode, the upstream is never touched,
ollama doesn't even wake up. If every interceptor returns =None=, the
request forwards transparently and the response streams back.

Phase 17.1 shipped 13 interceptors. Phase 18 has added 10+ more
(sysexport, sysscreenshot, !shell, @agent, synth_tool_call,
:tool, ??:explain, ?:cite, ~replay, >raw, prompt_cache).
Phase 18 is still adding more, one per
single-file landing; cloud failover is the first.

* Why it exists

opencode dispatches the user's message to the LLM the moment they
hit Enter — there is no plugin-side hook that fires *before* the HTTP
request leaves opencode. For org-llm to short-circuit a request
(handle =/sys*= locally, return a cached response, swap to cloud,
strip the MCP catalog from a system prompt, etc.) intercepting at
the HTTP layer is the only available seam.

The first interceptor that motivated the whole thing was
=intercept_sys_commands=: when the user types =/sysmenu= or
=/sysscroll-down=, the work happens entirely in the
[[file:../../extensions/opencode/src/sys-commands.tsx][TS plugin]] —
ollama waking up just to return an empty assistant turn was pure
waste. Now the proxy returns the empty response directly, the plugin
runs the action, and ollama stays asleep.

* Shipped interceptors (in order)

The order matters: every interceptor sees the request before the
next one does, and the first one to return a =ProxyResponse= wins.

Order matches =DEFAULT_INTERCEPTORS= in [[file:../../org_llm/llm_proxy.py][=org_llm/llm_proxy.py=]]; if
this table drifts again, regenerate by reading that list directly.
Short-circuiters are #1-13; mutators (modify the request, fall
through to forward) are #14-23; the conditional kill-switch
=intercept_local_only= is appended by =cli.py= when the user
flips =proxy_local_only=.

| # | Interceptor                       | What it catches                                                          |
|---+-----------------------------------+--------------------------------------------------------------------------|
|  1 | =intercept_no_llm_flag=          | =--no-llm= argument anywhere in the message → empty response            |
|  2 | =intercept_sysexport_command=    | =/sysexport [sidebar]= → write chat-export + return path/snapshot       |
|  3 | =intercept_sysscreenshot_command= | =/sysscreenshot= → run =org-llm screenshot=, return path                |
|  4 | =intercept_shell=                | =!shell <cmd>= prefix → run cmd locally (gated by =proxy_allow_shell_prefix=) |
|  5 | =intercept_agent_prefix=         | =@<agent>= prefix → stub pending preconfigured-agents roadmap entry     |
|  6 | =intercept_sys_commands=         | =/sys*= prefix in the latest user message → empty response              |
|  7 | =intercept_synth_tool_call=      | Tool-incapable model (gemma, phi3) + =tools= → prompt-engineered tool calls |
|  8 | =intercept_md_skills=            | =.md= slash with =exec:= frontmatter → run as subprocess, return stdout |
|  9 | =intercept_static_slashes=       | =/menu=, =/help=, =/config= → handwritten markdown response             |
| 10 | =intercept_probe_cache=          | Repeated provider probes (=GET /api/tags= etc.) → cached body           |
| 11 | =intercept_response_cache=       | Exact-prompt cache hit → cached response                                |
| 12 | =intercept_force_tool_call=      | =:tool <name>= prefix → pin =tool_choice= to that function              |
| 13 | =intercept_explain_prose_only=   | =??:explain= prefix → force =tool_choice: "none"= (prose only)          |
| 14 | =intercept_cite=                 | =?:cite <claim>= → force =search_notes= + raw-output system overlay     |
| 15 | =intercept_replay_history=       | =~<n>= prefix → replay the Nth-prior user prompt, optional suffix       |
| 16 | =intercept_raw_passthrough=      | =>raw <model> <prompt>= → strip system+tools+history, swap model        |
| 17 | =intercept_pii_redact=           | Redact secrets (API keys, tokens) before forwarding                     |
| 18 | =intercept_time_grounding=       | Inject current date into the system prompt before forwarding            |
| 19 | =intercept_model_routing=        | Route by query shape (cheap model for trivia, smart for code)           |
| 20 | =intercept_tool_call_repair=     | Fix common LLM-emitted malformed tool-call schemas                      |
| 21 | =intercept_qwen3_no_think=       | Auto-inject =/no_think= for qwen3 models                                |
| 22 | =intercept_prompt_cache=         | Inject =keep_alive= on local Ollama; mark Anthropic =cache_control= on largest system block |
| 23 | =intercept_prompt_slim=          | Strip the MCP catalog (~22 KB) from system prompts that don't need tools |
|    | =intercept_local_only=           | Catch-all kill switch (=proxy_local_only=true=) — appended only when set |

The full source with rationale comments is in [[file:../../org_llm/llm_proxy.py][=org_llm/llm_proxy.py=]];
56 unit tests pin behaviour in [[file:../../scripts/test_llm_proxy.py][=scripts/test_llm_proxy.py=]].

Two short-circuits aren't in the chain table because they fire from
inside =_forward= rather than the interceptor list:
- *cloud-first bypass* (=proxy_cloud_first=true=) — chat completions
  skip the local upstream and route directly through the same
  =_failover_to_cloud= machinery. Audit label =cloud_first=.
- *cloud failover on TTFB timeout* — local stalls past
  =proxy_first_byte_timeout_ms= → re-issue the request against
  cloud for THIS turn only. Audit label =cloud_failover=. On
  context-overflow (32k caps + a 64-tool MCP inventory) two
  retries follow: =cloud_failover_compressed_tools= (descriptions
  trimmed, schemas stripped) then =cloud_failover_no_tools=.

** Cloud failover (Phase 18, first interceptor)

The forward path now wraps the local =urlopen= with a tight time-to-
first-byte timeout (=proxy_first_byte_timeout_ms=, default 30000). When
the local upstream stalls past that threshold on a chat-completions
request, the proxy aborts the local connection and silently re-issues
the same body against the configured cloud provider for THIS request
only — single retry. Once the first byte arrives the socket timeout is
extended to 300s so legitimate slow streaming runs uninterrupted.

Pairs with [[file:../../extensions/opencode/src/slow-llm-watch.tsx][=slow-llm-watch.tsx=]]: the watcher nudges the user
toward a session-wide cloud switch (relaunch); the failover
interceptor is per-turn cover for the one stuck message — the user
gets an answer without a relaunch round-trip. Knobs:

- =proxy_cloud_failover_enabled= (default true)
- =proxy_first_byte_timeout_ms= (default 30000; bumped from 8000 in
  Phase 18.6 — cold-start prefill on thermally-throttled CPUs with
  heavy MCP tool inventories needed real headroom; 0 disables)
- =proxy_cloud_first= (default false) — when true, chat completions
  skip local entirely and route directly through =_failover_to_cloud=,
  saving the per-request 30s wait. Onboarding step 6c offers this
  automatically when free RAM falls below 1.2× the configured
  =chat_model='s footprint.

The cloud target is the same =cloud_endpoint_url= / =cloud_model= /
=cloud_provider= the rest of the app uses (see
[[id:510a135d-2a0c-4b0c-ac3a-2fd2ab80bf08][Cloud-or-local routing]]). Failover
audit entries show =intercepted_by="cloud_failover"=, distinguishable
from regular forwards in =scripts/audit_phase17.py='s output.

* Why it matters

- *Local model stays asleep on UX-only flows.* =/sysmenu= and friends
  don't burn watts spinning ollama up to return an empty turn.
- *Token waste drops.* =intercept_prompt_slim= strips the 22 KB MCP
  catalog from system prompts on plain-chat queries — that's faster
  TTFT against any model.
- *Bad tool calls don't fail the user.* =intercept_tool_call_repair=
  fixes common LLM-emitted JSON schema errors before opencode sees
  them and aborts the tool-use loop.
- *Composition over conditionals.* New behaviour = one new
  =intercept_<thing>= function, register it in =start_proxy='s
  default chain. No threading conditionals through opencode's request
  path.

** Prefix interceptor family (Phase 18.7)

A small set of typed prefixes lets the user shape a chat request
without going through the LLM's negotiation step. Each prefix is
detected at the proxy mutation layer; the prefix itself is stripped
from what the LLM sees, so the model only gets the residual query.

| Prefix             | Effect                                                                                     |
|--------------------+--------------------------------------------------------------------------------------------|
| =:tool <name>=     | Pin =tool_choice= to that function — model commits, no "should I call a tool?" branch     |
| =??:explain ...=   | Force =tool_choice: "none"= — model can't drift into a tool call, must answer in prose    |
| =?:cite <claim>=   | Force =search_notes= + system overlay nudging raw verbatim matches (audit-grade citation) |
| =>raw <model> ...= | Strip system + tools + history; route to the named model with just the bare prompt        |
| =~<n> [suffix]=    | Replay the Nth-most-recent prior user prompt; optional suffix appends                     |
| =!shell <cmd>=     | Run =cmd= locally and return stdout as the assistant turn (gated by =proxy_allow_shell_prefix=) |
| =@<agent> ...=     | Per-turn agent override — stub pending the preconfigured-agents roadmap entry             |

Use cases:
- =:tool code_search rotation matrix= — skip the model's wrong-
  tool-pick risk when you know the territory.
- =??:explain how cloud_first works= — when the model keeps
  searching the vault but you wanted prose.
- =?:cite the proxy timeout default= — get the literal note
  excerpts, no paraphrase.
- =>raw deepseek-r1 prove pi irrational= — benchmark a model
  with no MCP tools, no system prompt, no history.
- =~3 with --no-think= — re-run the prompt 3 turns back with a
  small variation appended; useful for A/Bing models or knobs.
- =!shell ls -la ~/org/.opencode= — quick file inspection from
  chat without leaving opencode (after enabling the gate).
- =@scribe write today's daily entry= — once preconfigured
  agents land, scope a single turn to a specific persona.

All seven are mutation/short-circuit interceptors — adding a new
one is a single function plus an entry in =DEFAULT_INTERCEPTORS=.
The cloud-failover, cloud-first, and compressed-tools-retry paths
inherit the prefix-mutated request for free.

** Synthetic tool calls for tool-incapable models (Phase 18.6)

Some local models — gemma, gemma2, gemma3, phi3, phi3.5, llava,
deepseek-coder — don't natively support OpenAI-style tool calling.
The launcher writes =tool_call: false= for them in =opencode.json=
so opencode doesn't even offer them tool schemas, but that means
the user loses MCP/RAG when they pick gemma. =intercept_synth_tool_call=
closes that gap in the proxy:

1. Detect a request whose =model= is on =_PROXY_NO_TOOL_STEMS= AND
   carries a =tools= array.
2. Strip =tools= and =tool_choice= from the body.
3. Inject a synthetic system prompt at the front of =messages=
   describing each tool with this contract:
   ~<tool_call>{"name": "...", "arguments": {...}}</tool_call>~
4. Force =stream: false= so we get one complete reply to parse.
5. Forward to the upstream directly (the interceptor short-
   circuits, calling =urlopen= itself with =req.upstream=).
6. Post-parse the reply for a =<tool_call>{...}</tool_call>= block;
   reshape into proper OpenAI =tool_calls= structure for opencode.
7. If no block is found, return the plain text — model chose not
   to call a tool.

Quality varies; gemma3 hits ~70-80% accuracy on simple single-tool
calls. Audit label =synth_tool_call=. Tools with verbose descriptions
get compressed via =_compress_tools_for_failover= (also reused on
cloud failover when the request would exceed the cloud model's
context window — see =cloud_failover_compressed_tools= path).

* Auditing & observability

The proxy ships a basic =AuditLogger= that writes a JSONL stream of
every intercepted/forwarded request to
=~/.local/share/org-llm/llm-audit.jsonl= when enabled. =/sysrecent=
surfaces the tail in chat (see
[[file:../../extensions/opencode/src/sys-commands.tsx][=sys-commands.tsx=]]).
