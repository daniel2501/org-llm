#+TITLE: Pi bridge — third conversational interface
#+FILETAGS: :wiki:concept:bridge:pi:
#+OPTIONS: toc:nil num:nil

* What it is

A TypeScript MCP-bridge extension that wires =org-llm='s tools
into [[https://pi.dev][Pi]] — Anthropic's IDE-adjacent CLI agent.
Pi is the third conversational interface alongside opencode and
Claude Code; the bridge gives Pi sessions full access to all
~64 org-llm MCP tools as Pi-native =org_llm_<name>= tools.

* Why Pi when opencode + Claude already exist

Each surface has its own strengths:

| Host          | Strength                                                  |
|---------------+-----------------------------------------------------------|
| opencode      | Deeply themable TUI, plugin system, custom slot rendering |
| Claude Code   | Anthropic's official CLI, GitHub integration, code edits  |
| Pi            | Per-turn dynamic system prompts (others are static once)  |

The Pi bridge unlocks the dynamic-system-prompt pattern: every
turn, the bridge re-renders the org-llm system prompt with
*current* vault stats / recent activity / active knob mix /
power-boost verdict. opencode and Claude Code only resolve the
system prompt once at session start.

* What gets installed

=org-llm pi --install= is idempotent. It:

1. Auto-installs Pi if missing (curl-based installer; pass
   =--npm= to prefer =npm install -g= instead)
2. Copies the bundled bridge extension to =~/.pi/extensions/=
3. Registers it in =~/.pi/config.json=
4. Verifies the bridge can reach the org-llm MCP server

The bridge is a single TypeScript file bundled inside the
=org_llm= Python package at
=org_llm/pi_extension/pi-org-llm.ts=. The install command
copies it out of the package; Pi loads the copy from
=~/.pi/extensions/= without further network access.

* Per-turn dynamic system prompt

The bridge intercepts Pi's request flow:

#+begin_example
User types message
   ↓
Pi extension hook fires
   ↓
Bridge renders org-llm system prompt:
  - Live vault stats (count notes, % embedded)
  - Recent activity from last N days
  - Active knob mix from Config
  - Hardware probe verdict
  - Top tags right now
   ↓
Bridge prepends to Pi's system prompt
   ↓
LLM call runs with FRESH context every turn
#+end_example

Compare with opencode / Claude where the system prompt is
captured at session-start and stays frozen until relaunch.

* Status surface

#+begin_example
$ org-llm pi --status
✓ Pi installed at /usr/local/bin/pi (v3.2.1)
✓ Bridge extension at ~/.pi/extensions/org-llm/
✓ Registered in ~/.pi/config.json
✓ org_llm_<name> tools registered: 64
✓ Last turn used: org_llm_search_notes, org_llm_get_node
#+end_example

The =--status= surface is also an MCP tool so any other host can
introspect bridge health.

* How to configure

** Env vars
- =ORG_LLM_PI_BRIDGE_DIR= — install location override (default
  =~/.pi/extensions/org-llm=)
- =ORG_LLM_DB= / =ORG_LLM_ORG_DIR= — same overrides; the bridge
  forwards them so the MCP subprocess hits the right vault
- =PI_CONFIG= — Pi's own config path override; the bridge
  honors it

** CLI flags
#+begin_src sh
org-llm pi --install                       # idempotent install (curl-based)
org-llm pi --install --npm                 # use npm install -g instead
org-llm pi --launch                        # install (idempotent) + exec into Pi
org-llm pi --status                        # health check (binary, bridge, config, tools)
org-llm pi --show                          # print the path to the bundled bridge
org-llm pi --reinstall                     # force re-copy of the bridge files
#+end_src

There is no =--uninstall=, =--update=, =--logs=, or =--restart=
flag; remove the bridge file from =~/.pi/extensions/= manually
(or =rm -rf= the dir) to uninstall.

** Conversational
- =/pi-status= slash command (when running inside Pi)
- The bridge auto-registers all org-llm tools as
  =org_llm_<name>= so the user never has to "enable" anything

* Source files

- =org_llm/pi_extension/pi-org-llm.ts= — the TypeScript bridge
  (bundled inside the Python package; copied to
  =~/.pi/extensions/= on install)
- =org_llm/cli.py:pi= — the install / status / launch verb
- =org_llm/mcp_server.py= — the same MCP server Pi spawns
