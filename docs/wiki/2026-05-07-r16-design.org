* Summary

*Summary.* R16 advances the bench from "can FOSS specialists do
basic edits?" (R15) to "can FOSS specialists be as good at coding +
OS work + org-mode life-management as Claude?" Mission-aligned task
catalog (org-agenda, weekly review, refile, captain's-log, real
Python coding, real shell ops) + statistical rigor (n=3 sampling) +
escalation routing + multi-specialist vote/judge + extended tool
surface (shell, python, pytest, git introspection).

*Expanded.* Five angles surfaced from R14/R15 learning are bundled
into R16 because they all need the same plumbing (variance
estimation, broader tool surface, mission-aligned task fixtures).
Doing them as separate rounds wastes harness work.

* Org-mode-specific advantages baked in (Tier S — biggest leverage)

*Summary.* The app has structured knowledge a generic FOSS model can't
infer from training data. Hand it to them as tools. Replaces "guess
at format" with atomic ops. Aligns with =manager pre-fetch + agent
narrates= memory: deterministic where possible, LLM where not.

| Lever | Tool / mechanism                                                                              | Why FOSS gets stronger                  |
|-------+-----------------------------------------------------------------------------------------------+-----------------------------------------|
| L7    | =add_property(file, heading_id, key, value)= — atomic =:PROPERTIES:= drawer write             | No guessing at drawer indent/syntax     |
| L7    | =set_todo_state(heading_id, state)= — validated state transition (TODO → STARTED → DONE)      | No invalid state writes                 |
| L7    | =add_heading(parent_id, level, title, props)= — atomic heading insert                          | No level/whitespace guessing            |
| L7    | =refile_to(source_id, target_path, position)= — atomic refile                                  | Removes "remove + insert" two-step      |
| L8    | Post-edit validation gate — every write tool runs =org-element-parse-buffer=, rejects if AST breaks | Free correctness ratchet         |
| L9    | Recipe pre-fetch — per task-shape, harness injects exact slots (=next_dec_number=, =today_date=, =due_in_7_days=, =candidate_ids=, =next_id_uuid=) | Model fills slots; never reasons about format |
| L10   | =vault_query(query)= — org-roam DB SELECT (=TODO=NEXT AND TAG:work AND DEADLINE<=2026-05-14=) | Structurally-aware search vs grep+regex |
| L11   | Schema-validated output — DEC, daily-log, weekly-review formats checked against schema pre-commit | Forces structural correctness          |

* Tool surface — extending toward Claude-Code parity

R15 has: =edit_file=, =write_file=, =read_file=, =find_canonical_id=,
=grep=, =list_dir=, =eval_elisp=, =load_elisp_file=.

R16 adds:

| Tool                | Purpose                                                          | Sandbox                                  |
|---------------------+------------------------------------------------------------------+------------------------------------------|
| =run_shell=         | Run a shell command in workdir; capture stdout/stderr/rc         | Cwd=workdir, timeout=30s, output cap 4KB |
| =run_python=        | Run a Python snippet in subprocess                                | Cwd=workdir, no extra deps, timeout=30s  |
| =run_pytest=        | Run pytest on a path; capture results structured                 | Wraps =python -m pytest=                 |
| =git_status=        | Read-only git state (status, diff, log)                          | =git -C workdir <subcommand>= passthru   |
| =org_query=         | Query org files via emacs --batch + org-element                  | Read-only org parsing                    |
| =add_property=      | Atomic =:PROPERTIES:= drawer write (Tier S L7)                    | Validates AST after write                |
| =set_todo_state=    | Validated TODO state transition (Tier S L7)                       | State machine enforced                    |
| =add_heading=       | Atomic heading insert at level/parent (Tier S L7)                 | AST validation                            |
| =refile_to=         | Atomic refile (Tier S L7)                                         | Source + target both validated            |
| =vault_query=       | org-roam DB SELECT (Tier S L10)                                   | Read-only                                 |
| =describe_elisp=    | =(documentation 'sym)= via emacs --batch (Tier A L15)             | Read-only                                 |
| =validate_org=      | Run =org-element-parse-buffer= on a file, return errors           | Read-only                                 |

Each new tool surfaces in =BROAD_TOOLS_PLUS_ELISP_PLUS_OS=. The
existing =D8 tool_surface= dial extends to {minimal, broad, full}.
=full= adds the OS tools.

*Security stance:* every tool stays inside the worktree (workdir
scope). No network calls. No mutations outside workdir. =run_shell=
+ =run_python= can still mess up the workdir, but worktrees are
disposable.

* Cell math (ramped — n=5, 13 variants, 27 tasks)

| Layer | Description                                          | Cells |
|-------+------------------------------------------------------+-------|

| L2    | Top-4 FOSS + Claude × 12 representative tasks × n=5  |   300 |
| L3    | Dial ablation: top-3 FOSS × 6 ablations × B1 × n=5   |    90 |

|-------+------------------------------------------------------+-------|
|       | Total                                                |   615 |

*Wall:* ~8-10 hours at current pace; with 4-way parallelism, ~2-3 hours.

*Cost projection:* ~$80-100 across all layers (Claude cells + 405b cells dominant). Within $100 cap.

** Lean v1 — feasibility-first (recommended starting point)

Layers 1 + 2 with full ramped sampling:
- L1: 65 cells (~30 min with parallelism)
- L2 (top-4 FOSS + Claude × 12 tasks × n=5): 300 cells (~2 hours with parallelism)
- Total: 365 cells, ~2.5 hours, ~$40-60

L3-L5 launched separately once L1/L2 yields the top-K winners + variance baselines.

* Pre-flight v2 — bigger and better

*Summary.* R15's preflight (=scripts/_round15_preflight.py=) was a 6-step
gauntlet that caught most integration bugs at the cost of one cheap
cell. R16's preflight v2 expands to 14 steps. The bar moves from "is
the harness syntactically OK?" to "does every dimension we plan to
test actually behave under realistic load?"

** Dry-run mode

New flag =--dry-run= on the R16 harness: executes every step EXCEPT
the API call. Returns a synthesized fake response (silent_noop, full
edit, fabrication, etc.) so the analysis + scoring + leaderboard +
monitor pipelines all exercise without spending. Catches plumbing
bugs at zero cost.

** K13 — Modal-self-hosted Kimi K2.6

*Summary.* OpenRouter's Parasail-served Kimi has 2-200s latency.
Modal-hosted Kimi on H100 should be sub-second per turn. Worth the
setup cost if R16 finds Kimi competitive on quality.

*Setup outline:*

1. =modal token new= (one-time auth)
2. Modal app: image with vLLM + kimi weights cached, H100 instance
3. Endpoint: =POST https://<user>--kimi-k2-6-serve.modal.run/v1/chat/completions=
4. =SpecialistTask.api_endpoint= override per-cell
5. Cost: ~$2-4/h H100; for 2 hours of testing, $4-8 dedicated

If Modal setup is non-trivial, defer to R17 (note in the harness
defines K13 but skips it unless =MODAL_KIMI_ENDPOINT= env var set).
