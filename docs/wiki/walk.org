* What walk is

Walk is *not* a retrieval mode. It's a knowledge-capture flow:
the LLM picks N notes worth attention, surfaces them one by
one, you explain what they mean to you in your CURRENT life,
and the LLM extracts atomic factual claims you made — saving
them to =llm-context.org= so future sessions cite the right
truth.

Think of it as "the LLM walking you back through your own vault
and asking you to teach it which facts still hold."

* When to walk vs ask

| Question shape                                | Reach for      |
|-----------------------------------------------+----------------|
| "What do I know about X?"                     | =ask=          |
| "Pull facts about X from my notes"            | =ask=          |
| "Which of my old notes still represent me?"   | =walk=         |
| "Help me update my context.org"               | =walk=         |
| "Walk me through note Y" (specific)           | =walk --pick=  |
| "Re-check the facts I told you last month"    | =walk --review=|

Walk pairs with [[id:e3333333-4444-5555-6666-cccccccccccc][staleness]]:
where the staleness sweep tags old notes =:stale:=, walk extracts
the *current truth* you assert about them and writes it to the
context overlay so RAG knows what supersedes what.

* The flow

1. =org-llm walk= picks =max_nodes= attention-worthy notes
   (orphans, recent captures, untagged-but-substantive) within
   the recent =--window-days=.
2. For each picked note, the LLM presents it to you and asks
   what it means TODAY.
3. You explain in natural language.
4. The LLM extracts *atomic factual claims you actually made*
   (skipping things you just paraphrased from the note) and
   proposes them.
5. You confirm; confirmed claims append to =llm-context.org=.
6. Optional disambiguation: if a claim contradicts something
   already in context, you (or the LLM) flag it via
   =walk_save_disambiguation=.

* Atomic facts + disambiguation

Phase 2026-04.08 — walk + opencode surfacing introduced two related concepts:

- *Atomic facts* — single-claim statements extracted from your
  explanation. =walk_remove_fact= MCP tool can target one by
  slug without rewriting surrounding facts.
- *Disambig placeholders* — when a fact contradicts something
  already in =llm-context.org=, the walk pipeline marks it
  with a placeholder line ("[Disambig: see context.org §X]")
  so future RAG knows the conflict exists. The placeholder
  auto-strips on every =context tangle= save.

* Conversational flow inside opencode

The launch flow's slot overrides + system prompt route walk via
the =walk_*= MCP tool family:

#+begin_src
User: walk me through what's been on my mind this week
Model: → walk_pick_targets(window_days=7, max_nodes=5)
       Returns: 5 candidate notes with titles + last-touched dates
Model: shows you the first one; asks for context
User: "I dropped this project; not pursuing it"
Model: → walk_extract_facts(...)
       Returns: ["Project X: dropped 2026-04 (formerly active)"]
Model: confirms; → walk_save_facts(...)
Model: moves to next note
#+end_src

The =walk_*= MCP tools are the granular surface; they enable
opencode-driven walks where the model paces the conversation
rather than the CLI prompting linearly.

* How to configure

** Env vars
- =ORG_LLM_DB= / =ORG_LLM_ORG_DIR= — the same overrides as
  every verb. Walk reads + writes the context overlay tangle.

** CLI flags
#+begin_src sh
org-llm walk                                  # default: track=notes, window=7d, max=5
org-llm walk notes                            # explicit
org-llm walk --window-days 30 --max-nodes 3   # broader window, smaller batch
org-llm walk -w 14 -n 10                       # short forms

# Pick specific notes (skip auto-selection)
org-llm walk --pick "kafka"                   # title fuzzy-match
org-llm walk --pick "<node-uuid>"             # exact ID
org-llm walk --pick "kafka" --pick "marx"     # multiple

# Re-walk previously-saved facts to re-confirm
org-llm walk --review                          # oldest first
                                               # cannot combine with --pick

# Dry-run: extract facts but don't append to context
org-llm walk --no-save
#+end_src

** Conversational (opencode / pi / MCP clients)

The walk_* MCP tool family (in [[file:../../org_llm/mcp_server.py][=org_llm/mcp_server.py=]]):

- =walk_pick_targets= — surface attention-worthy notes
- =walk_extract_facts= — pull atomic facts from a user explanation
- =walk_save_facts= — append confirmed facts to context overlay
- =walk_review_pending= — list facts not yet acted on
- =walk_save_disambiguation= — record a contradiction marker
- =walk_remove_fact= — delete a saved fact by slug
- =walk_undo_last_save= — back out the most-recent save
