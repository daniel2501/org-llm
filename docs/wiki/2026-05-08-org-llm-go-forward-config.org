* Executive summary

*Headline.* After 25 rounds of bench (R1-R25), 1019+ cells, and ~$90
in cumulative spend, =org-llm= can reliably operate on FOSS models
at *48-51× lower cost-per-quality-unit than Claude*. The default
scribe is K1-qwen30 (Qwen3-Coder-30B-A3B-Instruct) at $0.0005/qpt,
served via OpenRouter (Novita preferred). K2-kimi-k2.6 is the
high-stakes prose specialist; K11-qwen3coder is the elisp specialist
with budget cap; K8-deepseekV3 is the recovered all-purpose backup.
K6-llama70b and K7-qwen72b are dropped from production. K5-claude-
solo remains as a sentinel-only quality ceiling.

*Top 5 recommendations.*

1. *Default LLM = K1-qwen30 via OpenRouter Novita.* 5 of 5 rounds
   on the FOSS Pareto frontier; $0.0005/qpt; n=50 stable.

2. *High-stakes prose / DEC drafts = K2-kimi-k2.6 via Moonshot+
   Parasail.* Raw-quality leader at n=25+, but cap =max_tokens=
   at 4096 to prevent runaway prose.

3. *Cap K11 spend at $1.50/round.* Premium ($0.02/qpt) but
   strictly dominated by K1 except on B25-shaped elisp tasks.

4. *Self-host K1 + K2 via vLLM (deferred to R26 if R25 wall is
   acceptable).* Eliminates broker tool-format gaps (caused R18
   v1 wipe + R19 K8 collapse) and removes OpenRouter rate caps.

5. *Wire S1-S4 composition strategies in R26.* Hedged-strong, best-
   of-N, critique-revise, specialty routing — all currently
   orphaned constants. Strategy-effectiveness agent estimated
   80-120 LOC for combined wiring; biggest unrealized R20+ lever.

*Ongoing.* K20-foss-distill LoRA training completed on Together
(~$5, 10 min) but hosted endpoint deployment hit a config error —
A/B test deferred to R26.

*This doc updates with R25 final data when round completes.*

** Self-hosted vLLM (R26 work)

For K1 + K2, deploy dedicated vLLM endpoints on RunPod or Together:
- Eliminates broker tool-format quirks (R19 K8 collapse cause)
- Removes OR rate cap risk (R21-R23 402 cause)
- Sub-second TTFT vs 800ms-2s OR (Sp3 from walltime agent)
- Cost: $40-60/round at A100 80GB SXM, $0/round at idle
  (autoscale to 0 between rounds)

*RunPod caveat:* dockerArgs unreliable per PM2; use pre-baked
Docker image with =ENTRYPOINT= set. Don't pass training/serving
script via API.

*Together caveat:* fine-tuning works flawlessly; serving needs
dedicated endpoint with `min_replicas=1` (no scale-to-zero
serverless for fine-tuned models).
