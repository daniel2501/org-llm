*Harness file shows the ordering autopilot wanted* — so the patch did land
at the file level. But the *runtime* behavior in the in-flight v3

*Verdict.* Harness pin update *was applied to the file* but OR's runtime
fallback rolled K2 and K17 off-pin anyway. *Crucially*, K2 on DeepInfra in
v3 *worked* (~tool_calls~ for 5 iters, 5 edits applied) — meaning either
(a) DeepInfra's Kimi adapter was fixed between v2 02:00 and v3 02:33, or
(b) v2's K2/DeepInfra failure was transient. Either way, the v3 fix did
*not* take in the sense of "K2 routed to Moonshot" — the protective
re-route never executed. v3 succeeded by accident.


* 6. R19+ recommended PROVIDER_PINS

Goals: pick brokers that *demonstrably* honor OpenAI tool-call format for
the routed model; treat anything below ~1 in 5~ silent-iter rate as
acceptable; treat ~stop, 0 tool_calls~ on the first iter as fatal.

| model                                  | rec'd order                | rationale                                                                                            |
|----------------------------------------+----------------------------+------------------------------------------------------------------------------------------------------|
| moonshotai/kimi-k2.6                   | Parasail, Moonshot         | Parasail confirmed-working in R14–R17; Moonshot historical good. *Block DeepInfra explicitly* — broke in v2 (length/0-tools). v3 success on DeepInfra is one cell, not a trust signal. |
| moonshotai/kimi-k2-thinking            | Moonshot, Parasail, Novita | Novita worked once (fallback) but order matters for cache stability; prefer Moonshot if available.   |
| deepseek/deepseek-chat-v3-0324         | DeepInfra                  | v1 broke when DeepInfra-only without fallbacks; v2/v3 with fallbacks-allowed work; keep DeepInfra primary, leave allow_fallbacks=True so OR can rescue. |
| deepseek/deepseek-r1                   | DeepInfra                  | only data point is historical; keep.                                                                 |
| qwen/qwen3-coder-30b-a3b-instruct      | Novita                     | 4/7 holds clean; "no choices" + SiliconFlow silent-text mark fallback as worse. Keep Novita primary, no SF in chain. |
| qwen/qwen-2.5-72b-instruct             | DeepInfra                  | 11/14 success but 12/14 had silent-text mid-loop iters — works because retry rescues. Acceptable for now; cap iterations conservatively. |
| qwen/qwen3-coder                       | Together                   | 1/1 clean; keep.                                                                                     |

*Suggested code-shape change.* Add an explicit deny-list to complement the
allow-order, so OR can fall back but not to a known-broken backend:

#+begin_src python
PROVIDER_PINS = {
    "moonshotai/kimi-k2.6": {
        "order": ["Parasail", "Moonshot"],
        "ignore": ["DeepInfra"],   # broke tool-format on v2
        "allow_fallbacks": True,
    },
    "qwen/qwen3-coder-30b-a3b-instruct": {
        "order": ["Novita"],
        "ignore": ["SiliconFlow"],  # silent-text on v2 K1 fallback
        "allow_fallbacks": True,
    },
    "meta-llama/llama-3.3-70b-instruct": {
        "order": ["DeepInfra"],
        "ignore": ["AkashML"],      # silent_noop on v2
        "allow_fallbacks": True,
    },
    "z-ai/glm-4.6": {
        "order": ["SiliconFlow", "Z-AI"],
        "allow_fallbacks": True,
    },
    # rest unchanged
}
#+end_src

OpenRouter ~provider.ignore~ is the supported field for excluding a
backend even with ~allow_fallbacks=True~.
