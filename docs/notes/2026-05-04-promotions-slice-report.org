* Objective

*Summary.* Stand up the SSSS (see-something-say-something)
substrate so specialist agents have somewhere to write typed
notices, without yet wiring any agent to use it. Two actions:
(1) added the =Notice= SQLAlchemy class to =org_llm/db.py=, and
(2) created =org_llm/notices.py= with a single =notice(...)=
writer. Substrate-only on purpose — no dispatch, no thresholds,
no specialist call sites. The =promotions= wiki page is the
design context this slice realizes the bottom-up half of.

* Decisions

** Schema chosen

Took the suggested schema verbatim. No deviations. Column order in
the model matches the brief; SQLAlchemy emits them in that order
when creating the table (verified against =.schema notice= output).

** Migration wiring

No new migration code needed. =_migrate_in_place()= already calls
=Base.metadata.create_all(engine)= unconditionally on existing DBs
(db.py lines 455–458, comment "New TABLES introduced over time …
need to be created on existing DBs that pre-date them"). That call
is idempotent — adding the =Notice= class to =Base.metadata= is
sufficient for both fresh and existing installs to pick up the
table on next =make_engine()= call. This is the same path
=AgentBaseline=, =CrewLog=, =VaultFact=, =SensorLog=, and
=InsightEngagement= ride.

* Open questions

- =dedup_key= semantics — captured but unused. The brief frames it
  as substrate ("collapse repeats at the read layer once that
  exists"). No index on it yet; the read layer will likely want
  one. Flagging for the dispatch-design pass, not now.

- Timestamp format includes microseconds + =+00:00=
  (=datetime.now(timezone.utc).isoformat()= default). =History= and
  =CrewLog= use =isoformat(timespec="seconds")+"Z"= — second
  resolution, =Z= suffix. I followed the brief's literal spec
  (=datetime.now(timezone.utc).isoformat()=) which gives microsecond
  precision and explicit offset. Both are valid ISO-8601 UTC; if
  the read layer needs to join =Notice.timestamp= against
  =History.timestamp= literally, this becomes friction. Easy to
  switch later — flagging now.

- Payload size — no truncation cap. Logbook has =_DEFAULT_BODY_CAP
  = 1500=. Specialists could in principle =notice()= a full LLM
  response. Not bounding it for now (substrate gathers, doesn't
  judge), but worth a cap once we see real data.

* Gotchas

- =sqlite3 ~/.local/share/org-llm/org-llm.db= raised "database is
  locked" twice during verification, once right after the
  =make_engine()= invocation finished (engine handle still
  releasing). A 2-3 second pause cleared it both times. Not a
  code defect — just local DB contention from running the
  helper-write and CLI-read back-to-back. Worth knowing for
  future verification scripts: insert =sleep 2= between
  =uv run= writes and =sqlite3= reads.

- =Base.metadata.create_all()= path in =_migrate_in_place= is the
  reason no explicit migration code is needed. The function name
  suggests it only handles in-place column additions, but it
  also creates whole new tables — the implementation comment at
  lines 452–454 spells this out. Future readers may grep for
  "ALTER TABLE notice" expecting to find migration wiring;
  there is none, by design.

- The =__allow_unmapped__ = True= flag on =Base= silenced no
  warnings here, but it's required because other classes in
  =db.py= have plain-Python attribute aliases SQLAlchemy 2.x
  would otherwise complain about. =Notice= inherits cleanly.
