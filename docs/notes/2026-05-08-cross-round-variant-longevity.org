* Summary

*Summary.* R15-R19 churned 19 K-IDs. Only *K1-qwen30* is a true 5/5
non-zero carry-over (K5-claude-solo also 5/5 but is a sentinel).
K11 + K2 form the next durable tier. Nine K-IDs already retired
(K3, K4, K10, K12, K13, K14, K16, K18, K19). R19 surfaced two new
collapses: K8-deepseekV3 (2.5 mech/cell, down from R17 frontier-winner)
and K6-llama70b (7/10 silent_noops). The R20+ FOSS-roster expansion
is *K20-foss-distill* (LoRA on Qwen3-Coder-30B distilled from
K2+K8+K11), training in flight on Modal at publish time.

*Expanded.* R15 launched 9 variants (K1-K9). R16 added K10-K14;
only K11+K13 actually executed. R17 piloted K15-K19; K15+K17
survived, K16/K18/K19 died on invalid IDs or 404s. R18 ran 10
variants but a worktree-add concurrency bug killed 90/140 cells.
R19 ran the same 10-variant pool on B1 layer1 + 8-task layer2;
K8/K6 collapses are the surprise. K20 is the only net-add for R20+
unless an external FOSS release lands.

* 6. K20-foss-distill integration plan once training lands

*State at publish.* Per =2026-05-08-r19-lora-progress.org=: app
=ap-9ATcS6Bac42FhQiquOr7HL= on Modal, checkpoint shards loaded,
eval dataset truncated, training loop entered (12 steps). Adapter
→ =/vol/k20-foss-distill/=; manifest at =k20_manifest.json=.

*Step-by-step integration.*

| # | step                                                  | gate                          |
|---+-------------------------------------------------------+-------------------------------|
| 1 | wait for =k20_manifest.json= write                    | training loss curve sane      |
| 2 | verify val−train ≤ 0.5 at every epoch boundary        | abort + restart if above      |
| 3 | deploy =07_modal_serve_k20.py= → vLLM endpoint        | =modal app list= shows serve  |
| 4 | stash bearer in =pass org-llm/cloud/modal-foss-lora/bearer= | =pass show= returns       |
| 5 | stash URL in =pass org-llm/cloud/modal-foss-lora/url= | =/v1/models= returns 200      |
| 6 | add K20 to =VARIANTS= in =_round20_dials.py=          | snippet §5 of LoRA prep       |
| 7 | run =recipe_ab_harness.py= K20 vs K11 on B1+B5+B11+B25+B26 | n=20 per cell            |
| 8 | blinded Opus judge via =recipe_ab_judge.py=           | display + edit-acc separately |
| 9 | decide vs pre-committed bar                           | adopt / narration-only / kill |
|10 | if adopted: K20 → R20 frontier tier (n=15)            | promotion logged in synthesis |

*A/B bar.* Display-text quality K20 ≥ K11+3; edit-accuracy K20 ≥
K11−5; blinded Opus rater via =recipe_ab_{harness,judge}.py=.

*Decision rule.* Both cleared → adopt frontier. Display-only +3
but edit −>5 → narration-only role. Display <+3 → discard run,
revisit dataset.

*Variant snippet* — see
=2026-05-08-r19-prep-lora-foss-distill.org= §5 for the full
=SpecialistTask(handle="K20-foss-distill", ...)= literal.

*Risks.* Training divergence — abort built into SFTConfig
eval_strategy. Serve cold-start — pre-warm side-pool like K15.
K20 inherits K8 R19 collapse — A/B vs K11 not K8 (base mismatch).
Voice over-fit — edit-acc bar catches; narration-only fallback.
Edit-acc < K1 — K1 + K20 share Qwen3-Coder-30B base, K20 SHOULD
match-or-beat K1 on edit-acc.
