* Top-line
  The bug is reasoning-token exhaustion at small max_tokens; F5/F6
  alone do not save you when the prompt is deliberation-shaped, but
  F7/F8 (concise + directive prompt) reliably unblock kimi at the
  current 3000 budget — recommended fix is "tool_choice=required +
  reasoning.exclude=true + concise system" plus raising the floor
  to ~8000 max_tokens for safety.

  Caveats:
  - ~tool_choice="required"~ assumes every specialist call has tools
    AND wants a tool. Audit call sites: if any pass an empty/optional
    tools list expecting a chat-only reply, gate on a flag instead.
  - The 8000 floor doubles a normal call's worst-case cost ceiling but
    the empirical hit on the simple-prompt path stays at ~$0.0004
    because finish happens long before 8000 tokens.

* Notes / interactions discovered
  - *F5/F6 are NOT a complete fix on their own.* When the prompt is
    deliberation-shaped (e.g. system asks for step-by-step reasoning
    or user invites weighing options), kimi spends 1200+ reasoning
    tokens before the budget runs out. ~tool_choice="required"~ at
    max_tokens=300 still produces ~finish_reason="length"~ with zero
    tool_calls. F5 only works because the *current* default prompts
    happen to be terse enough. Any specialist persona that nudges
    deliberation (e.g. "think carefully") re-triggers the bug.
  - *F7 (minimal prompt) and F8 (anti-reasoning directive) work but
    are call-site changes.* They're effective but harder to enforce
    than a one-line API param flip; should be added as a "tip" in
    docstrings for new specialist personas, not relied on.
  - *F9 (provider routing) does not measurably change behavior.* The
    default provider was Parasail; pinning to ~order=["Moonshot"]~ ran
    a bit slower (8.8s vs 2.6s) and ~sort=throughput~ was identical.
    Not worth carrying.
  - *OpenRouter ~reasoning~ param is partially broken for kimi.*
    ~reasoning.enabled=false~ does NOT stop kimi from deliberating;
    it just relocates the deliberation from the ~reasoning~ field into
    visible ~content~ (still consumes the budget, still finish=length).
    ~reasoning.exclude=true~ hides the field but billed reasoning
    tokens are unchanged. ~reasoning.max_tokens=50~ was ignored
    (got 2083 chars of reasoning back). Treat this param as cosmetic
    for kimi.
  - *The cheap winning combo is F5 + concise system prompt + 8000
    floor.* The recommended patch above hits all three with one edit.

    root cause — confirm they're seeing reasoning_tokens consumed in
    completion_tokens_details. If yes, the budget bump and the
    prompt-shape fix are complementary, not competing.
