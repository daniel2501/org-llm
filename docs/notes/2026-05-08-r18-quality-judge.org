remains the cost-quality pareto, K6-llama70b's mech lead is mostly

shootout), and 12 layer3 B1 (dial sweep, K6 + K7 only).

Caveat: 90 of 140 cells errored at =git worktree add= concurrency —
that's a test-harness defect (DEC infra, not model quality). Ranking
below uses the 50 results we can judge.

* 1. Methodology

** Quality rubric (0-20)

| dim                  | weight | rule                                                       |
|----------------------+--------+------------------------------------------------------------|
| edit correctness     |      6 | task accomplished; no broken links / syntax / no-op when expected work |
| edit minimality      |      4 | only the asked change; no wholesale rewrites or churn      |
| constraint compliance |     4 | scope_strict respected; append_only honored; no fab UUIDs / authors |
| tool-use efficiency  |      3 | minimal iterations + tools; no thrashing                    |
| output presentation  |      3 | no stacked docstrings; no broken brackets; no trailing newline issues |

20 = pristine; 15 = good w/ minor flaw; 10 = task done but real
defect; 5 = silent_noop on a doable spec OR severe defect; 0 =
fab-UUIDs / actively destructive / unreachable code.

** How quality differs from mech score

Mech score in v2 rewards link-count + diff-size proxies.  It does NOT
penalize:

- broken org-mode bracket syntax (=]])= instead of =]]=)
- nested-bracket disasters (=[[id:...][[[id:...][...]]]]=)
- wholesale paraphrasing of unrelated table content
- only-prefix linking (label = "Phase 2026-05.16" not full phrase)
- fabricated UUIDs (K7 d6_tool seeded =12345678-...= instead of
  prefetch IDs)
- unreachable-code edits (K1 B7 added a 2nd =return= block)
- stacked docstrings (K6/K7 B7 inserted comments duplicating body)
- broken org headings (K6 d9_relaxed dropped opening paren on heading)

Quality score reads the diff and re-prices these.

** What flips on quality

- *K6-llama70b*'s mech-leader status (R18 v2 leaderboard #3 by total
  score) is heavily inflated by B1's mech 24.  Quality-judged it's
  worse than K7 because of *table-mangling* (line 17 broke a
  table-row by replacing the leading `| =verbatim=` cell with a
  bracketed link, no pipe; new content is not a valid org-table row)
  and *nested-bracket disasters* on the see-also TODO link.  The
  count-based mech rewards 12 links; quality penalizes that 12 of
  them include 2 broken ones.
- *K7-qwen72b*'s d6_inline mech 20 is the worst-ranked cell relative
  to mech: 7 separate broken-bracket edits, including =])force; today
  it's= (sentence inside truncated link), =relaunch.]]= (period
  swallowed by label), and =])]= chains.
- *B20 is the cleanest case for the score-vs-quality gap*: all four
  variants scored mech 0 (silent_noop is taxed as a fail) but the
  task itself was a no-op trap — clean abstain *should* be max
  quality. Quality 18 for all four.
- *B13's identical 1-line LICENSE bump* shows mech severely
  understates the cleanest possible outcome: 4-way perfect tie at
  mech 2, quality 20.
- *K1 B7 (mech 18, quality 6)* is the single biggest false positive:
  the harness rewarded an edit that is literally unreachable code (a
  duplicate function body added below an existing =return=
  statement). This is destructive in spirit even though the existing
  function continues to work.

* 6. R18 v3 + R19 implications

** R18 v3 priorities (small fixes, before R19)

1. *Fix worktree concurrency* — 90 of 140 cells died at =git
   worktree add=. This kills all signal density. Add a filesystem
   mutex or pre-create worktrees serially before the parallel scoring
   pass. Without this, R18 v2's "leaderboard" is stat-noise.
2. *Add mech penalty for broken brackets* — regex over inserted
   lines: =\]\)= without a paired =\[\[=, =\]\]\]\]= or deeper, and
   =\[\[\[\[= chains. Each occurrence: -3 mech.
3. *Add mech penalty for fab-UUIDs* — already partially flagged via
   =id_in_workdir: false= but =wrap_categories.creative= didn't fire
   for K7 d6_tool's =12345678-...=.  Tighten the predicate.
4. *Promote silent_noop on 'no-op trap' tasks* — B20's spec is
   a no-op trap; all four cells abstaining should score mech 12-15,
   not 0. Add a per-task =expected_diff_size= floor.
5. *Add mech penalty for unreachable-code AST changes* — for Python
   diffs, a post-edit Python AST walk that flags duplicate =return=
   in a function body. K1 B7 would drop from mech 18 to ~5.

** R19 implications

- *K5-claude-solo is the quality ceiling for sentinel/judge roles*
  (mean 17.3, n=8 across diverse tasks) but stays barred from
  production scribe (FOSS-only rule). It is the right Opus-judge
  blind-rater seed.
- *K1-qwen30 is the cost-quality pareto* (12.8 quality at $0.0008/cell;
  about 1/180th the cost of K5 for ~74% of the quality). Promote to
  default scribe in R19 long-horizon fixtures.
- *K7-qwen72b is FAST + CHEAP but produces broken-bracket diffs at
  alarming rate*. Consider gating K7 behind a post-edit org-mode
  link-validator (a small Python pass that re-parses the diff with
  =org_link.parse= and rejects unbalanced brackets). Without that
  gate, K7's productivity is illusory.
- *K6-llama70b is unsafe on long-context wrap tasks*. R19 should
  exclude K6 from B1-shaped wrap-cross-link tasks until provider /
  prompt is improved (or use it only with d8_minimal where it
  degrades to silent_noop, which is at least non-destructive).
- *Long-horizon BK1-BK5 fixtures (R19)*: choose K1-qwen30 + K5-claude
  as the dual-track. K7 only with bracket-validator gate.
- *Quality-judge automation*: this report was hand-graded.  R19
  should ship a small =scripts/quality_lint.py= that runs the same
  bracket / fab-UUID / unreachable-code / heading-integrity checks
  the harness misses, and folds them into the next mech-score
  iteration so the leaderboard tracks quality more closely.
