#+title: Kimi K2.6 silent-output diagnosis — Agent 1 fix-slate F1..F4
#+date: 2026-05-07

* Top-line

  *=reasoning.enabled=False=* (per-request, in OpenRouter body) reliably
  unblocks Kimi K2.6: tool_calls fire on every probe, =reasoning_tokens=0=,
  =completion_tokens=33=, cost <$0.0003/call, wall 1.4-2.0s — at the
  default =max_tokens=3000=. F1 (raising =max_tokens=) also works on
  every synthetic prompt I tried but does not address the root cause
  (uncapped reasoning chain) — recommend pairing both.

* Methodology note

  My synthetic prompts (simple, heavy-system, multi-turn) never
  reproduced the round-14 silent-no-op (=$0.018=, =finish_reason=length=,
  empty content) — Kimi emitted tool_calls every time at =max_tokens=3000=.
  That implies the round-14 cell's reasoning chain consumed ~3000 output
  tokens because of *real specialist-task context* (vault prefetch,
  inlined target files, broad tool surface, multi-turn iterations) that
  my fixtures don't approximate. The fixes below are still load-bearing
  because (a) F1 raises the ceiling so that real chain-of-thought has
  headroom, and (b) =reasoning.enabled=False= eliminates the failure
  mode at its source.

* F2 — message.* keys (every Kimi response)

  =['content', 'reasoning', 'reasoning_details', 'refusal', 'role', 'tool_calls']=

  Kimi exposes its chain via =message.reasoning= (string) and
  =message.reasoning_details= (list of typed segments). =usage.completion_tokens_details.reasoning_tokens=
  reports the count separately from visible-output tokens — but both are
  charged against =max_tokens=. Our pipeline already extracts
  =message.tool_calls= and =message.content=; we don't need to parse
  =reasoning= unless we want to surface it for debugging.

* Recommended patch for =org_llm/specialist.py=

  Two-tier fix: (1) raise the global =max_tokens= ceiling so reasoning
  has headroom on real specialist tasks, (2) per-model "is reasoning
  model with runaway-thinking risk" hook that injects
  =reasoning.enabled=false= for Kimi. Do *not* blanket-disable for all
  reasoning models — F4 shows deepseek-r1 produces strictly worse output
  without thinking.

  Rationale:
  - =max_tokens 3000 → 8000= adds headroom for legitimate chain-of-thought
    without making the failure mode silent (any model that needs >8000
    tokens of reasoning to emit a tool call is misbehaving and should
    surface).
  - =reasoning.enabled=False= for Kimi specifically: tool_calls remain
    correct (verified in F3f and F3f'); cost drops 4-7x; latency drops
    2-4x. We lose Kimi's CoT for that one model, which is fine — Kimi
    K2.6 was already chosen for its tool-use behavior, not its
    reasoning depth (use deepseek-r1 for reasoning-heavy work).
  - Set is allow-list (currently 1 model). Future Moonshot variants can
    be added explicitly; reasoning models known to need their CoT
    (deepseek-r1, qwen3-thinking, etc.) are unaffected.

* Open follow-ups

  - *Synthetic-prompt failure not reproduced.* I could not get Kimi to
    spend its full =max_tokens= budget on reasoning with any prompt I
    fed it (peak completion was ~221 tokens). The round-14 cell's $0.018
    silent no-op implies either real-task context (vault prefetch +
    inlined target files + broad tool surface across multiple
    iterations) drove the chain past 3000, or there's a Parasail/upstream
    quirk that fires under specific conditions. Either way, the
    recommended patch eliminates the runaway-reasoning failure mode at
    its source.
  - *Logging.* Per round-13 post-mortem, =SpecialistResult= currently
    discards raw payloads. Independently of this fix, capturing
    =completion_tokens_details.reasoning_tokens= per iteration would
    let us spot Kimi-style runaway thinking before it manifests as a
    silent failure.
  - *=success= heuristic.* Round-13 post-mortem already proposed
    =success = bool(edits_applied) or bool(text_output)=. With this in
    place, future Kimi-shaped silent failures fail loudly.
