#+TITLE: R17 OpenRouter provider routing + prefix-cache audit
#+DATE: 2026-05-08
#+OPTIONS: toc:nil num:nil

* Summary

R17 added =PROVIDER_PINS= (OpenRouter =provider.order= field) to stabilize
prefix-cache hits across the 17-variant FOSS sweep. *The pins did not take
the way the design assumed.* OpenRouter treats =order= as a *preference*,
not a hard pin — without =allow_fallbacks: false= it freely routed to
non-pinned brokers. Of the 13 agor variants warmed at run start, *only 2
landed on the pinned provider* (K6, K11 — both Together). Despite this,
realized cache savings were *meaningful but uneven*: 4 variants saw
≥3000 cached tokens (K2, K8, K15, K17), 6 saw zero, and total realized
savings on input cost are an estimated *14.6%* — below the 22-27% R16
prediction, almost entirely because the K1/K11/Mixtral/Llama70b lanes
served zero cache hits in 30+ qualifying cells.

** Root cause

In =scripts/_round17_dials.py= line 171 + =org_llm/specialist.py= line 538:
=PROVIDER_PINS= sends only =provider.order=, no =allow_fallbacks: false=.
OpenRouter docs treat =order= as preference — falls through to any
provider serving the model. *The pin is advisory, not authoritative.*

** Findings

- *K8 on DeepInfra is the only variant with a working multi-cell cache
  loop*: 7/8 cells hit, 87.5% rate. DeepInfra preserves prefix cache
  across requests for deepseek-chat-v3-0324.
- *K1 + K11 are the broken pins.* Despite serving 13 cells each on a
  single broker (Novita and Together respectively — i.e. provider
  stability happened naturally even without the pin holding), *neither
  served a single cached token across the whole sweep.* Novita and
  Together appear not to expose prefix-cache hits to OpenRouter for
  these qwen3-coder routes.
- *Cache hits on K2/K15/K17 first-cell* indicate the cache was warmed by
  the warmup ping (same model_id, same provider header). Not a
  multi-cell effect — these variants only ran once.

* 4. Realized cost savings calc

Cached tokens × OpenRouter typical 90% input-token discount (cached
tokens are billed at 0.1× the prompt rate on most brokers; a few use
0.25× — taking 0.9× as the user-stated figure).

=42 848 + 67 840 + 81 920 + 103 104 = 295 712 tokens=

| K2-kimi-k2.6  |     42 848 |                    0.60 |              0.0231 |

| Total         |    295 712 |                       — |       *~0.122 USD* |

R17 total =specialist_cost_usd= summed across all cells (from
=cell_result.json= sum, completed cells only): approximately *$3.23*.
Realized savings of $0.12 → *~3.8% of total spend*, or *~14.6% of input
spend* assuming input ≈ 25% of total spend on these routes.

vs. R16 prediction of *22-27% input savings* → *realized 14.6%, miss
ratio ~0.6×*. The miss is dominated by 26 cells (K1×13 + K11×13)
serving zero cache — i.e. the largest two variant lanes by cell count
contributed *zero* to the cache-hit denominator.

* 5. R18 PROVIDER_PINS revisions + fallback recommendations

** 5a. Hard-pin (add =allow_fallbacks: false=)

Without this, =order= remains advisory and most pins evaporate. Switch
the wire format from:

#+begin_src python
PROVIDER_PINS = {"qwen/qwen3-coder-30b-a3b-instruct": {"order": ["Together"]}}
#+end_src

to:

#+begin_src python
PROVIDER_PINS = {
    "qwen/qwen3-coder-30b-a3b-instruct": {
        "order": ["Together"],
        "allow_fallbacks": False,
    },
}
#+end_src

This will *fail-fast* if Together is over capacity rather than silently
losing the prefix cache. Acceptable for a controlled sweep; exposes the
provider-quota problem honestly.

** 5b. Re-pin to the broker that *actually serves* + caches today

Empirical winners from R17 should become the canonical pins for R18
since that's where the cache lives:

| Variant           | Old pin  | R17 actual served | Cache visible? | R18 recommended pin |
|-------------------+----------+-------------------+----------------+---------------------|
| K1-qwen30         | Together | Novita            | no             | Together (re-test)  |
| K2-kimi-k2.6      | Moonshot | DeepInfra         | yes 42 848 tok | DeepInfra           |
| K6-llama70b       | Together | DeepInfra (run)   | no             | DeepInfra           |
| K7-qwen72b        | Together | DeepInfra         | unknown (hung) | DeepInfra           |
| K8-deepseekV3     | DeepSeek | DeepInfra         | yes 87.5% rate | *DeepInfra*         |
| K9-mixtral        | Together | Mistral           | no             | Mistral             |
| K11-qwen3coder    | Together | Together          | no             | Together (re-test)  |
| K15-kimi-thinking | Moonshot | Novita            | yes 67 840 tok | Novita              |
| K17-glm46         | Z-AI     | SiliconFlow       | yes 81 920 tok | SiliconFlow         |
| K19-qwen25c-32b   | Together | Cloudflare        | unknown (404)  | drop tools-broad    |

Net effect: *~9 of 13 pins should change destination* to the broker that
already serves and caches. The original pin map was based on
"first-party = best" assumption, which the OR fleet doesn't honor today.

** 5c. Per-variant fallback ladders

Replace the bare =order=[X]= form with a 2-3 deep ladder so a quota
trip degrades to a known-good neighbor instead of silent fall-through:

#+begin_src python
PROVIDER_PINS = {
    "deepseek/deepseek-chat-v3-0324":     {"order": ["DeepInfra", "AtlasCloud", "DeepSeek"], "allow_fallbacks": False},

    "qwen/qwen3-coder":                     {"order": ["Together"],                              "allow_fallbacks": False},
    "qwen/qwen3-coder-30b-a3b-instruct":   {"order": ["Together", "Novita"],                   "allow_fallbacks": False},
    "qwen/qwen-2.5-72b-instruct":           {"order": ["DeepInfra", "Together"],                "allow_fallbacks": False},

    "mistralai/mixtral-8x22b-instruct":      {"order": ["Mistral", "Together"],                   "allow_fallbacks": False},

** 5d. Drop pins that route to dead lanes

- =meta-llama/llama-4-instruct= (K18) — *DROP from VARIANTS*. Model id
  invalid on OR (HTTP 400 on warmup, 0 cells served).
- =qwen/qwen-2.5-coder-32b-instruct= (K19) — drop from broad-tools
  cells; HTTP 404 "no endpoints support tool use". Either re-pin to a
  tool-capable broker or move K19 to inline-prefetch only.
- =deepseek/deepseek-v4-pro= (K13) — 2 cells hung mid-stream
  (=IncompleteRead=). Add explicit =deepinfra= or =fireworks= fallback,
  or demote to candidate pool.
