*Summary.* R24 v1 produced 130 specialist ~run_end~ events across 71 cell
artifacts. R19_WIRING deny-lists held cleanly for K8 (recovered 38→164),
K11 (Together exclusive), K17 (no AkashML routing), and K6 (no AkashML).
K6's 4/10 silent_noops were *DeepInfra-served, not provider-mismatched* —
the deny-list cannot fix a model the pinned broker also fumbles. K7's
−693 is a *fabrication blast on the variant side* (DeepInfra and Novita
both delivered tool calls fine; the model just hallucinated edits that
didn't exist). One new R24 finding: *K17-glm46 on DeepInfra max-iters
loops* with 125k–197k cached tokens per run — an unbounded retry pattern
that wasn't visible in R18 (only 1 K17 cell there). R25 should flip K17
back to SiliconFlow-first deny-DeepInfra and demote K6 from baseline.

*Expanded.* Five sections: per-variant pin-vs-actual; confirmed-broken
new in R24; confirmed-working; deny-list verification per R19_WIRING;
length / text-with-no-tool cells; and a recommended R25 PROVIDER_PINS.

* 7. R25 advisory — concrete routing changes

Top-5 actionable, ranked by expected delta:

1. *K17-glm46.* Add ~"ignore": ["DeepInfra"]~ to ~z-ai/glm-4.6~. Force
   SiliconFlow only; if SiliconFlow is slow, accept the latency rather
   than DeepInfra's max-iters loop. R24 SiliconFlow K17 was 1/2 success
   in 80s vs DeepInfra K17 was 0/6 in 170–190s each — DeepInfra both
   slower *and* failing. Drop Z-AI from the order list (still never
   actually serves; was an R18 carryover).
2. *K6-llama70b — demote from baseline to test pool.* DeepInfra (the
   pinned broker, AkashML denied) still produced 4/10 silent_noops on
   the same model. This is a *model + broker* failure, not a routing
   problem deny-list can fix. Move K6 to side-pool / S38 adversarial
   strategy testing only, like K7. If retained in baseline, add an
   ~ignore-DeepInfra~ and pin to a different broker — but R24 has no
   data on alternates for L3.3-70b (R18 saw 1 AkashML cell, also bad).
   Cleanest path: drop K6 entirely until R25 surveys Together / Fireworks
   for L3.3-70b tool-call adapter quality.
3. *K7-qwen72b.* Already a fabrication-side disaster (−693 from
   hallucinated edits, not broker). If kept as adversarial in S38, add
   ~"ignore": ["Novita"]~ to ~qwen/qwen-2.5-72b-instruct~ (32k cap is a
   real cliff). DeepInfra-only with the variant-side bracket-disaster
   problem isolated to the model contract is a cleaner experiment.
4. *K2-kimi-k2.6 max_tokens cap.* Set ~max_tokens=4096~ or lower on
   Parasail-served K2 cells *or* enable Modal route. 13 length-truncated
   cells at 23–29k chars is most of K2's silent-text taxonomy in R24.
   This is harness-side, not PROVIDER_PINS, but it belongs in the same
   stability story.
5. *Add a "deny SiliconFlow when serving slow-first-token" health check.*
   SiliconFlow K17 took 80s for a successful run vs DeepInfra K17's 170s
   max-iters fail — counter-intuitively SiliconFlow is the *fast and
   correct* path here. The broker bypass that lets DeepInfra win (8 vs
   2) suggests an OpenRouter-side latency-balancing heuristic working
   against us. R25 may need a strict ~order~ override (no fallbacks)
   for K17 specifically, accepting SiliconFlow availability risk to
   gain quality.
